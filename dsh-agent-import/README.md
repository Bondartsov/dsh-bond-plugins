# dsh-agent-import — движок импорта сессий из других агентов

`@local/dsh-agent-import` — движок миграции: он находит сессии в хранилищах
Claude Code, Codex, ZCode (CLI и v2), KiloCode и OpenCode и переносит выбранную
сессию в DSH как **нативную сессию DSH** — с тем же именем, проектом, историей и
логом инструментов. Такую сессию можно открыть в DSH и **продолжить**: агент
видит импортированную историю, а новые ходы дописываются в тот же лог.

Движок доступен двумя способами: HTTP-маршруты `/agent-import/*` (для панели) и
инструмент модели **`agent_import`**. Собственной панели у плагина больше нет —
в интерфейсе осталась только страница `main` как цель для deep-link; вход
пользователя в миграцию даёт вкладка **«Миграция»** пакета `dsh-migrate`.

## 1. Что это и какую задачу решает

У каждого агента свой формат лога. DSH хранит сессии как холодный V4-артефакт с
плотной нумерацией событий и строгими инвариантами; «скопировать jsonl» в него
нельзя — нужен корректный лог `turn/start → step/start → system/message →
user/message → session/title → assistant/message → tool/call → tool/result →
step/end → turn/end`. Плагин делает именно это:

1. адаптер источника читает чужой лог **только на чтение** и собирает
   нормализованный транскрипт (`user` / `assistant` / `tool`);
2. синтезатор строит валидный V4-лог;
3. запись идёт через Host-сервис `sessionPersistence` (`create` → `append` →
   `flush` → `close`) — физическое кодирование делает бэкенд DSH;
4. артефакт **перечитывается холодным чтением**: это та же проверка, которую DSH
   делает перед продолжением сессии;
5. сессия прикрепляется к workspace своего проекта и попадает в ledger;
6. идентификатор детерминирован от `(source, foreign id)`, поэтому повторный
   импорт — no-op, дублей нет.

## 2. Требования

- **DeepSeek Harness 2.x**, десктопная сборка (Electron).
- Host-сервисы: `tools` и `webServer` (объявлены в `inject`). Для импорта
  дополнительно нужны `sessionPersistence` и `sessionQuery`; для `reimport` —
  `workspaceRegistry`; для `continue` — `sessionController`. Необязательные:
  `sessionProjectionCache` (имя в холодной строке списка) и `workingDirectory`
  (каталог по умолчанию для сессии без проекта). Отсутствие обязательного
  сервиса даёт внятную ошибку «the Host does not publish …», а не тихий сбой.
- Node.js 20+ и pnpm 9+ — только для установки из репозитория.
- Чужие хранилища на этой машине (хотя бы одно) — иначе все источники ответят
  «недоступен».
- Windows/PowerShell не обязательны для самого движка; SQLite читается встроенным
  ридером без внешних зависимостей.

## 3. Установка из репозитория `dsh-bond-plugins`

```powershell
git clone https://github.com/<ваш-логин>/dsh-bond-plugins.git
cd dsh-bond-plugins
powershell -NoProfile -ExecutionPolicy Bypass -File install.ps1
```

Только этот пакет:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File install.ps1 -Only "@local/dsh-agent-import"
```

План без изменений: `install.ps1 -WhatIf`. Нестандартный профиль:
`-ProfileDir "<путь-к-профилю>"`.

Скрипт снимает резервную копию `package.json` и `cordis.patch.yml` профиля в
`<профиль>\backups\<ДД.ММ.ГГГГ>-<ЧЧММСС>`, добавляет пакет в `dependencies` как
`link:`, добавляет его в `dsh.profile.bundles` и запускает `pnpm install`.

**Нужен полный перезапуск DSH**: маршруты и инструмент — Host-часть, а ⟳ её не
подхватывает. Заодно новый процесс гарантирует, что клиентский бандл попал в
`window.__DSH_BOOT__` (эта композиция кэшируется на время жизни Host).

## 4. Как пользоваться

### Через интерфейс

Пользовательская точка входа — вкладка **«Миграция»** пакета `dsh-migrate`: она
показывает дерево «проект → сессии», галочки, импорт выбранного батчами и
обновление уже импортированных сессий. Своей панели у этого пакета нет; страница
`main` с ключом `agent-import` осталась только целью deep-link (если другой
плагин откроет её по ключу).

### Через инструмент модели

`agent_import` с обязательным `action`:

| `action` | Параметры | Что делает |
|---|---|---|
| `scan` | `source?`, `limit?` (по умолчанию 50, максимум 500), `offset?` | инвентарь источников, сессий, проектов и счётчик уже импортированного |
| `search` | `query`, `source?`, `limit?` | фильтр по имени сессии и пути проекта |
| `import` | `source`, `id`, `path?`, `force?` | импорт одной сессии; `force` переимпортирует даже при записи в ledger |
| `update` | `source`, `id`, `path?` | дописать в копию только то, что появилось в источнике после импорта |
| `reimport` | `source`, `id`, `path?` | пересобрать копию заново (старая уходит в архив) |
| `verify` | `sessionId` | прочитать сессию слоем запросов DSH и сказать, видна ли она в списке |
| `continue` | `sessionId`, `prompt` | возобновить сессию и отправить промпт — **тратит один запрос к модели** |
| `ledger` | — | что уже импортировано (до 200 последних записей) |
| `assets` | — | скилы, плагины, MCP-серверы, конфиги чужих агентов |
| `mcp_plan` | — | записать готовый фрагмент `- insert:` для MCP-серверов |
| `copy_skills` | `names[]` | скопировать чужие скилы в `~/.dsh/skills` |
| `ui` | — | попал ли клиентский бандл в манифест страницы (диагностика) |

Ответ инструмента — `{action, text, data}`: `text` — готовый человекочитаемый
отчёт (русский), `data` — тот же объект, что вернул бы соответствующий маршрут.

### Через HTTP

База `http://<host>:<port>/agent-import/*`, JSON. Полный контракт с полями
ответов — в [docs/ENGINE-CONTRACT.md](docs/ENGINE-CONTRACT.md). Кратко:

- **GET**: `/inventory`, `/tree`, `/ui`, `/ledger`, `/assets`;
- **POST**: `/import`, `/import-batch`, `/update`, `/reimport` (требует
  `{"confirm": true}`), `/verify`, `/continue`, `/mcp-plan`, `/skills`.

Ошибки всегда `{"error": "<КОД>: <сообщение>"}` с кодом `400 BAD_ARGUMENT`,
`403 NOT_OWNER` (запрос не из GUI DSH), `405` (метод), `409 CONFIRM_REQUIRED`,
`500 IMPORT_FAILED`.

## 5. Настройка

Файла настроек и переменных окружения у плагина нет. Есть пути и пределы.

### Что и где читается (чужие хранилища — только чтение)

| Источник | `id` | Где лежит |
|---|---|---|
| Claude Code | `claude-code` | `~/.claude/projects` |
| Codex | `codex` | `~/.codex/sessions`, `~/.codex/state_5.sqlite`, `~/.codex/session_index.jsonl` |
| ZCode CLI | `zcode-cli` | `~/.zcode/cli/db/db.sqlite` |
| ZCode v2 | `zcode-v2` | `~/.zcode/v2/sessions` |
| KiloCode | `kilo` | `%KILO_HOME%` либо `~/.local/share/kilo/kilo.db` |
| OpenCode | `opencode` | `~/.local/share/opencode/opencode.db` |

### Куда пишется (только домашний каталог DSH)

| Что | Путь |
|---|---|
| Ledger импортов | `~/.dsh/agent-import/ledger.json` (`DSH_HOME` учитывается) |
| Предложение MCP | `~/.dsh/agent-import/mcp-proposal.yml` |
| Скилы | `~/.dsh/skills/<имя>` |
| Сессии | обычный стор сессий DSH через `sessionPersistence` |

`DSH_HOME` переопределяет домашний каталог DSH; `KILO_HOME` — расположение
KiloCode. Оба читаются один раз на процесс.

### Пределы и параметры

| Параметр | Значение | Смысл |
|---|---|---|
| `limit` у `scan`/`search` | 50 по умолчанию, максимум 500 | размер страницы |
| `import-batch` | не более 50 элементов | одна HTTP-порция выбора |
| тело запроса | 16 КиБ (batch — 256 КиБ) | защита от случайных гигантских тел |
| `perProject` у `/tree` | по умолчанию 60, максимум 500 | сколько сессий проекта отдавать |
| `perSourceLimit` у `/tree` | по умолчанию 500 | сколько сессий источника сканировать |
| `continue` | ожидание до 180 с, промпт с таймаутом 60 с | дождаться хода в том же логе |

### Ассеты: что переносится и что нет

- **скилы** копируются в `~/.dsh/skills` (чужие каталоги не трогаются; уже
  существующее имя пропускается);
- **MCP-серверы** предлагаются фрагментом `- insert:` — плагин **никогда** не
  правит `cordis.patch.yml` профиля; секреты остаются ссылками на переменные
  окружения;
- **плагины** только инвентаризируются: рантайм чужого агента не переносится
  (другая платформа), переносятся их скилы и MCP;
- **конфиги** (`~/.claude/settings.json`, `~/.codex/config.toml`,
  `~/.zcode/settings.json`, `~/.kilocode/settings.json`) только перечисляются с
  размером — не читаются, потому что содержат секреты.

## 6. Архитектура кратко

| Половина | Файл | Роль |
|---|---|---|
| Host | `index.js` + `lib/` | 13 маршрутов, инструмент `agent_import`, операции |
| Client | `client.js` | только страница `main` (key `agent-import`) как цель deep-link; строка в левой панели, кнопка в шапке чата и вкладка в правом доке удалены |

Слои Host:

```text
index.js            маршруты + инструмент (единственная точка входа)
  lib/api.js        таблица операций, общая для маршрутов и инструмента
  lib/scan.js       инвентарь, поиск, дерево проектов (кэш на Host)
  lib/sources/*     адаптеры источников: status/listSessions/readSession
  lib/import.js     импорт, update, reimport, проверка V4, детерминированный id
  lib/events.js     синтезатор V4-лога
  lib/ledger.js     ledger импортов (~/.dsh/agent-import/ledger.json)
  lib/assets.js     скилы, плагины, MCP, конфиги, копирование скилов
  lib/paths.js      DSH_HOME, домашние пути, чтение head/tail, JSON-lines
```

Состояние: **весь Host**, клиент не хранит ничего (`client.js` только рисует
страницу и ходит в те же маршруты). Долгоживущее — ledger и `mcp-proposal.yml`;
остальное вычисляется заново при каждом запросе.

Почему инструмент и маршруты используют одну реализацию: два потребителя
(модель и браузер) не должны расходиться в поведении. Поэтому `createOperations(ctx)`
один, а `index.js` — тонкая обёртка над ним.

## 7. Ограничения и типичные ошибки

- **Чужие хранилища неприкосновенны.** Плагин только читает; ни один маршрут не
  пишет в чужой стор и не читает секреты (`credentials.json`, `auth.json`,
  `*.key`, `*.pem`, таблицы `account`/`credential`).
- **Своей панели нет.** В интерфейсе вход в миграцию даёт вкладка «Миграция»
  пакета `dsh-migrate`; страница `main` этого пакета — только deep-link.
  Замечание для владельца: `dsh-migrate` несёт **собственную** реализацию движка
  (свои маршруты `/dsh-migrate/sessions/*`) и читает ledger'ы прежних плагинов как
  read-only фолбэк, то есть `/agent-import/*` сегодня не вызывается панелью.
  Контракт этого пакета от этого не перестаёт работать — он самодостаточен.
- **Изображения** из чужой истории заменяются текстовым плейсхолдером: DSH не
  умеет воспроизводить изображения, которых нет в его хранилище вложений.
- **Вызов инструмента без записанного результата отбрасывается** (иначе шаг
  остался бы незакрытым); счётчики `droppedCalls`/`droppedResults` есть в отчёте.
- **ZCode v2 хранит только текст** — потеря инструментов указывается в отчёте.
- **Проект сессии отсутствует на этой машине** — копия прикрепляется к рабочему
  каталогу DSH по умолчанию; исходный путь остаётся в ledger и предупреждениях.
- **`already-imported` вместо дубля** — это норма: id детерминирован от
  `(source, id)`. Чтобы перезаписать, нужен `force` (импорт) или `reimport`
  (пересборка с архивом прежней копии).
- **`busy`** у `update`/`reimport`: в копии открыт ход (выполняется или был
  прерван). Закройте сессию и повторите.
- **`diverged`/`needs-reimport`**: источник переписал историю (компакция, правка)
  либо запись сделана до появления отметок объёма. Обновление отклоняется, чтобы
  не продублировать переписку; выход — `reimport`.
- **`continue` тратит запрос к модели** и ждёт до 180 с. Пустой `reply` не значит
  ошибку: ответ мог ещё не дойти до лога — смотрите сессию в UI.
- **`403 NOT_OWNER`** при ручном вызове маршрута: запрос пришёл не из GUI DSH
  (`Sec-Fetch-Site` не `same-origin`). Заголовок отсутствует — запрос
  считается своим (для не-браузерных клиентов).
- **`ui` говорит «не зарегистрирована»** — клиентский бандл не попал в манифест:
  нужен полный перезапуск DSH (композиция кэшируется на процесс), ⟳ не поможет.
- **Схема инструмента уже, чем реализация.** `index.js` читает
  `args.includeSubagents`, но в `parameters` этого поля нет — через инструмент
  модели контекст субагентов передать нельзя (через маршруты `/import`,
  `/import-batch`, `/reimport` — можно). А действие `reimport` инструмента не
  передаёт `confirm`, который требует одноимённый маршрут: маршрут защищён от
  случайной пересборки, инструмент вызывает операцию напрямую. Расхождение
  зафиксировано как известное, код документацией не меняется.
- **Один битый источник не скрывает остальные**: `scan` показывает его
  «недоступен» с причиной.
- **Плагину нужен `webServer`**: без него маршруты не регистрируются (инструмент
  при этом продолжает работать).

открываться.
