# dsh-bond-plugins

[![CI](https://github.com/Bondartsov/dsh-bond-plugins/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/Bondartsov/dsh-bond-plugins/actions/workflows/ci.yml)

Коллекция плагинов для **DeepSeek Harness (DSH)** — десктопного агентского харнесса.
Все плагины написаны под спецификацию DSH 2.x, не имеют внешних зависимостей и работают
как на Windows, так и на Linux/macOS (кроме служебных PowerShell-скриптов).

Репозиторий — единственный источник правды: обновление плагинов = `git pull` + перезагрузка
плагинов в DSH. Никаких сборок, никакого npm-реестра, никаких «скачайте zip».

## Версии и релизы

`git pull` приносит снапшот репозитория целиком, но версии и релизы у плагинов **независимые**:
тег и GitHub Release вида `<каталог>-v<версия>` (например `peer-bus-v2.1.0`) появляются только у того
плагина, который менялся. Остальные плагины в этом релизе не участвуют и своих версий не меняют.
Сверку `plugins.json` с `package.json` каждого плагина делает CI (`.github/workflows/ci.yml`),
создание релиза по тегу — `.github/workflows/release.yml`.

## Требования

- **DeepSeek Harness 2.x** (десктопная сборка; web-версии не существует — это Electron-приложение).
- **Node.js 20+** и **pnpm 9+** (менеджер зависимостей профиля). Если pnpm нет:
  `npm install -g pnpm`.
- Windows: PowerShell 5.1+ (для `install.ps1` / `update.ps1`).
- Свободный доступ на запись к каталогу профиля DSH:
  `%USERPROFILE%\.dsh\profiles\desktop` (Windows) или `~/.dsh/profiles/desktop`.

## Установка

```powershell
git clone https://github.com/<ваш-логин>/dsh-bond-plugins.git
cd dsh-bond-plugins
powershell -NoProfile -ExecutionPolicy Bypass -File install.ps1
```

Скрипт:

1. снимает резервную копию `package.json` и `cordis.patch.yml` профиля в `<профиль>\backups\<ДД.ММ.ГГГГ>-<ЧЧММСС>`;
2. добавляет плагины в `dependencies` профиля как `link:` на каталоги этого репозитория;
3. добавляет их в `dsh.profile.bundles`;
4. выполняет `pnpm install`, создавая junction-ссылки в `node_modules` профиля.

Затем **перезагрузите плагины** кнопкой ⟳ в интерфейсе. Если после ⟳ не появилась Host-часть
(панель, маршрут, инструмент) — полностью перезапустите DSH: клиентские бандлы обновляются
через ⟳, а Host-код загружается только при старте процесса.

Полезные варианты:

```powershell
# только часть плагинов
install.ps1 -Only "@local/dsh-peer-bus","@local/dsh-migrate"

# посмотреть, что было бы сделано, ничего не меняя
install.ps1 -WhatIf

# профиль в нестандартном месте
install.ps1 -ProfileDir "D:\dsh\profiles\desktop"
```

## Обновление

```powershell
cd dsh-bond-plugins
powershell -NoProfile -ExecutionPolicy Bypass -File update.ps1
```

Скрипт откажется работать, если в репозитории есть незакоммиченные изменения (чтобы не потерять
ваши правки), сделает `git pull --ff-only`, переустановит зависимости профиля и напомнит про ⟳.

Так как плагины подключены **ссылками**, обновлённый код сразу лежит на месте — но уже
запущенный процесс может держать старую версию в памяти.

| Что изменилось | Как применить |
|---|---|
| Клиентская часть (`client.js`, стили, локали) | ⟳ перезагрузка плагинов |
| Host-часть (`index.js`, `lib/*`, маршруты, инструменты) | ⟳ перезапускает изменившиеся записи Loader, но часть состояния кэшируется на всё время жизни процесса (например, вердикт «пакет не клиентский»). Надёжно — **полный перезапуск DSH** |
| И то и другое | перезапуск DSH |

Практическое правило: сначала ⟳; если поведение не изменилось — перезапустите DSH. Строка
«Reload DSH» показывает `pending` и `restartReason` — если там непусто, reconcile не справился и
нужен перезапуск.

## Как узнавать об обновлениях

Обновление **не приходит само**: плагины исполняют код внутри DSH, поэтому молча
подменять их нельзя — установку запускает владелец. Узнать о новой версии можно
тремя способами:

| Способ | Что сделать | Что видно |
|---|---|---|
| Страница **Reload DSH** в DSH | открыть панель, нажать «проверить обновления» | «Версия плагинов: b940b91» и итог: «обновлений нет» либо «`peer-bus` 2.1.0 · обновление: 1 плагин (`peer-bus` 2.1.0 → 2.2.0)» |
| Скрипт | `powershell -NoProfile -ExecutionPolicy Bypass -File update.ps1 -Check` | таблица «плагин · версия сейчас · изменился ли каталог», «изменено плагинов: N из 7», версии до/после; ничего не меняется |
| GitHub | подписаться на Releases репозитория (Watch → Releases) | письмо или лента о новом выпуске; подробности — в `CHANGELOG.md` плагинов |

### Версии плагинов независимы

`git pull` приносит снапшот репозитория целиком — «только peer-bus» он не умеет. Но
версии и релизы у плагинов свои (см. «Версии и релизы» выше), поэтому и проверка, и
обновление печатают **что изменилось фактически**, а не «обновлено всё».

`update.ps1 -Check` сравнивает текущий коммит с `origin/main` и раскладывает
изменения по каталогам плагинов:

```text
Проверка обновлений плагинов dsh-bond-plugins
  установлена версия 07675c1, доступна c86462d

  плагин                    версия сейчас   каталог в HEAD..origin
  peer-bus                 2.1.0           изменился
  dsh-migrate              1.0.0           —
  dsh-reload               1.1.0           —
  composer-cost            1.0.0           —
  composer-cost-day        1.0.0           —
  dsh-subagent-indicator   1.0.0           —
  dsh-agent-import         1.0.0           —

  изменено плагинов: 1 из 7
  изменения: peer-bus 2.1.0 → 2.2.0
  коммиты этих плагинов:
    · c86462d feat(peer-bus): 2.2.0
```

Обычное обновление печатает то же самое после `git pull`:

```text
  обновлён 1 плагин: peer-bus 2.1.0 → 2.2.0; остальные 6 без изменений
```

Приехали только документы или workflow-файлы — скрипт так и скажет: «Каталоги
плагинов не изменились», и `pnpm install` не запустит.

`-Only <каталог>` (`-Only peer-bus`) не делает частичный pull — такого не
существует; он сужает отчёт и решает, нужен ли `pnpm install`:

```text
  Внимание: файлы всех плагинов обновляются вместе, версии и релизы независимы; изменённым оказался: peer-bus.
  плагин dsh-reload не изменился — pnpm install не нужен.
```

В DSH кнопка на странице «Reload DSH» показывает те же факты, посчитанные на
Host-половине плагина (`git diff` по каталогам + версии из `package.json` обеих
ревизий): «`peer-bus 2.1.0` · обновление: 1 плагин (`peer-bus` 2.1.0 → 2.2.0)».

Проверка в DSH и `-Check` делают одно и то же: `git fetch` и сравнение текущего
коммита с `origin/main`. Ни та ни другая **ничего не устанавливают** — ни
`git pull`, ни `pnpm install` не запускаются, в `.git` обновляются только ссылки
на удалённые ветки.

Нашли обновление — применяйте вручную:

```powershell
cd dsh-bond-plugins
powershell -NoProfile -ExecutionPolicy Bypass -File update.ps1
```

…и затем ⟳ **или** полный перезапуск DSH по таблице из раздела «Обновление»
(если менялся `client.js` — только полный перезапуск).

Что именно изменилось — смотрите в `CHANGELOG.md` каждого плагина и во вкладке
[Releases](../../releases) этого репозитория.

## Как это устроено

DSH собирает рабочую композицию из **профиля** — каталога `~/.dsh/profiles/desktop`:

- `package.json` — зависимости (наши плагины как `link:` на этот репозиторий) и список
  `dsh.profile.bundles` — какие бандлы загружать;
- `cordis.patch.yml` — слой конфигурации: модели, провайдеры, MCP-серверы, права, тема;
- `node_modules` — установленные пакеты (для `link:` это ссылки на исходники).

Плагин DSH состоит из двух необязательных половин:

| Половина | Файл | Что может |
|---|---|---|
| **Host** | `index.js` (+ `lib/`) | регистрировать HTTP-маршруты, инструменты модели, подписываться на события агентов, работать с сервисами DSH (сессии, воркспейсы, хранилища) |
| **Client** | `client.js` | рисовать элементы интерфейса через слоты (панели, кнопки, ячейки), подписываться на стор-сервисы |

Связка «что загружать» лежит в `package.json` самого плагина (`dsh.client`, `dsh.bundle`), а
собственный слой конфигурации — в `cordis.patch.yml` рядом с кодом.

## Безопасность и откат

**Плагин исполняет код в процессе DSH.** Это не «настройка», а полноценное расширение: он видит
ваши сессии, файлы и может менять профиль. Поэтому:

- ставьте только из репозитория, которому доверяете;
- `install.ps1` **всегда** делает резервную копию профиля перед изменениями;
- откат: скопируйте `package.json` и `cordis.patch.yml` из `<профиль>\backups\<метка>` обратно в
  профиль, выполните `pnpm install`, перезапустите DSH;
- если приложение не запускается после установки — верните профиль откатом и сообщите о проблеме.

Секреты плагины **не хранят**: `dsh-migrate` пишет их в переменные окружения пользователя, а в
конфигурации остаются только ссылки на переменные.

## Разработка

Структура плагина:

```
<плагин>/
├── package.json          # имя, версия, dsh.client / dsh.bundle, files
├── index.js              # Host-половина (если есть)
├── client.js             # Client-половина (если есть)
├── cordis.patch.yml      # собственный слой конфигурации
├── locale/ru.json        # локали (ru/en)
├── lib/                  # внутренние модули Host-половины
├── test/                 # тесты: node --test "test/*.test.mjs"
├── README.md             # что это и как пользоваться
├── docs/DESIGN.md        # как устроено и почему так
└── CHANGELOG.md          # история изменений
```

Запуск тестов (у каждого плагина свой набор):

```powershell
cd peer-bus
node --test "test/*.test.mjs"
```

Соглашения репозитория:

- **никаких внешних зависимостей** в плагинах — только встроенные модули Node и React из хоста;
- **никаких личных путей** в коде: пути берутся из `DSH_PROFILE_DIR` / `USERPROFILE`;
- **даты** в текстах и именах файлов — `ДД.ММ.ГГГГ`; ISO — только там, где требует машина;
- **цвета** в интерфейсе — только токены темы `--dsw-alias-*`, без хардкода;
- **сторож-тесты обязательны**: на каждое правило поведения — тест, который падает, если правило
  нарушили;
- формулировки для владельца — только десктопные: «перезагрузка плагинов ⟳» или «перезапуск DSH».

## Совместимость

Плагины используют публичные сервисы и слоты DSH, но интерфейс между версиями меняется.
Проверено на сборке из `C:\Users\<user>\AppData\Local\Programs\DeepSeek Harness` (DSH 2.x, Node 22–26).
Если после обновления DSH плагин «не виден» — сначала ⟳, затем перезапуск; если не помогло,
смотрите `docs/DESIGN.md` плагина: там перечислены используемые сервисы и слоты, которые нужно
сверить с новой версией.
