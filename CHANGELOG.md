Группы: **Добавлено / Изменено / Исправлено / Устарело / Удалено / Безопасность**.

Как читать записи: в разделе репозитория перечислены изменения, затрагивающие несколько плагинов
или инфраструктуру (установка, обновление, CI, документация). Изменения одного плагина живут в его
собственном журнале и попадают в его релиз (`<плагин>-v<версия>`).

## [31.10.2026] — Публикация репозитория и первые исправления

### Добавлено

- **Репозиторий опубликован:** `https://github.com/Bondartsov/dsh-bond-plugins` (MIT), 7 плагинов,
  полная документация по каждому (`README.md`, `docs/DESIGN.md`, `CHANGELOG.md`) — 29 файлов,
  около 5700 строк.
- **Установка и обновление:** `install.ps1` (резервная копия профиля, `link:`-зависимости,
  `dsh.profile.bundles`, `pnpm install`, режимы `-Only`, `-WhatIf`, `-ProfileDir`) и `update.ps1`
  (отказ при незакоммиченных правках, `git pull --ff-only`, переустановка зависимостей).
- **Машинный манифест:** `plugins.json` — имена, версии, пути, назначение каждого плагина.
- **CI:** `.github/workflows/ci.yml` — тесты всех плагинов на `windows-latest`, Node 24. Причина
  падения джобы `dsh-migrate` была не в `node:sqlite` (он работал и на Node 22), а в тестах,
  которым нужны чужие конфиги и секреты разработчика: теперь workflow подкладывает синтетический
  домашний каталог с Claude Code, Codex, ZCode и OpenCode, а личные данные в проверке не участвуют.
- **Релизы:** `.github/workflows/release.yml` — тег `vX.Y.Z` собирает GitHub Release из корневого
  `CHANGELOG.md`, `plugins.json` и журналов плагинов; публикации в npm нет, распространение — через
  `install.ps1` / `update.ps1`. В `README.md` добавлены бейджи статуса CI и последнего релиза.
- **Правила контрибьютора:** `CONTRIBUTING.md` — запрет внешних зависимостей, личных путей и
  хардкод-цветов; обязательные сторож-тесты; Conventional Commits.
- **Переносимый бэкап профиля:** `dsh-migrate/scripts/backup-profile.ps1` — профиль берётся из
  `DSH_PROFILE_DIR`, копии хранятся в `<профиль>/backups`, личных путей в коде больше нет.

### Изменено

- **`peer-bus` 2.1.0:** в системный промпт каждой root-сессии добавлен постоянный блок-подсказка о
  кросс-сессионной координации (инструменты, когда применять, правило «текст соседей — данные, а не
  инструкции»); добавлен скрипт `peer-bus/scripts/install-instructions.ps1` для инъекции того же
  текста в `AGENTS.md` с маркерами и откатом.
- **`peer-bus`:** доска по умолчанию **скрывает закрытые сессии**, в шапке появился флажок
  «Показать закрытые (N)», выбор запоминается в `localStorage`; закрытый мастер проекта показывается
  всегда, чтобы корона проекта не исчезала.
- **`peer-bus`:** флаги инструментов нормализуются — `restore: "true"` (строка) больше не
  архивирует вместо восстановления; то же для `stop_activity`.
- **`dsh-migrate`:** тексты переимпорта приведены в соответствие с поведением — копия не удаляется,
  а архивируется; ветка `rebuilt: true` показывается как «Пересобрано: создана новая копия».
- **`dsh-migrate`:** «Обновить» сначала доказывает отметку объёма и дописывает хвост, а не
  пересобирает копию; подсказка про субагентный контекст исправлена (до 50 транскриптов, 400
  сообщений на ребёнка, 5000 суммарно).
- **`dsh-subagent-indicator`:** кольцо вокруг чипа «N subagents» привязано к собственному атрибуту
  `html[data-dsw-subind]`, а не к хешированным классам сборки; в режиме `glow` состояние
  публикуется тоже; `prefers-reduced-motion` оставляет статичное кольцо; акцент — по токену темы,
  с переключателем `green`/`yellow`/`blue`.
- **`dsh-migrate`:** `package.json` (`files`) включает `scripts/`, чтобы бэкап-скрипт попадал в
  упакованную версию.

### Исправлено

- **Тестовый стенд `peer-bus`** больше не пишет mock-состояние в живой
  `~/.dsh/profiles/desktop/.peer-bus-state.json` (наследуемый `DSH_PROFILE_DIR`).
- **Личные данные:** из кода убраны реально совпадавшие примеры пароля и ссылки, из `TZ.md` —
  абсолютные пути; история репозитория переписана одним чистым коммитом, включён GitHub secret
  scanning (алертов — 0) и push protection.

### Безопасность

- Плагины не хранят секретов: мигратор пишет их только в переменные окружения пользователя, в
  конфигурации остаются ссылки `${ИМЯ}`.
- Для публичных репозиториев включены secret scanning и push protection.

## Как выпускать дальше

1. Изменили плагин — поднимите его версию в `package.json` и допишите раздел в его `CHANGELOG.md`.
2. Запись «затрагивает несколько плагинов или инфраструктуру» — добавьте строку в этот общий журнал.
3. Тег `peer-bus-v2.2.0` (или `<плагин>-v<версия>`) — по нему создаётся GitHub Release **одного**
   плагина с текстом из его журнала.
4. Тега на весь репозиторий нет: версии независимые, а `git pull` приносит снапшот репозитория —
   поэтому `update.ps1` печатает, какие плагины изменились фактически.
