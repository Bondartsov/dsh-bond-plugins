# `@local/dsh-migrate` — миграция из чужих агентов в DSH

**Плагин:** `@local/dsh-migrate` · **версия:** 1.0.0 · **bundle:** запись `include: migrate`
(идентификатор `migrate`) · **половины:** Host (`index.js` + `lib/`) + Client (`client.js`).
Техническое описание — [docs/DESIGN.md](docs/DESIGN.md); история — [CHANGELOG.md](CHANGELOG.md);
исходное ТЗ — [TZ.md](TZ.md).

---

## 1. Что это и какую задачу решает

Плагин переносит в DSH работу, накопленную в других агентских CLI: **сессии** (историю
разговоров вместе с инструментальными ходами) и **ассеты** (скилы, MCP-серверы, секреты,
плагины, инструкции и конфиги). Всё это — **один плагин с одной панелью и двумя вкладками**:
«Сессии» и «Ассеты». Сессия импортируется как **нативная сессия DSH** и её можно продолжить
штатным резюмом; ассеты переносятся **идемпотентно** — с журналом (ledger) того, что уже
импортировано, статусами «новый / уже есть / обновит / дубль / конфликт» и предпросмотром
до записи. По умолчанию **ничего не отмечено**, чужие каталоги агентов открываются **только на
чтение**, а запись в профиль (MCP-строки) и в переменные окружения (секреты) требует
отдельного подтверждения владельца.

Возможности:

- **Источники сессий:** Claude Code, Codex, ZCode CLI (v1), ZCode v2, KiloCode, OpenCode.
- **Дерево «проект → сессии»** с каскадными галочками, поиском, фильтром по источнику,
  скрытием субагентных сессий и опцией «Контекст субагентных».
- **Живой прогресс импорта**: процент, «i из N», текущий этап каждой сессии, журнал строк,
  итог и подсказка про перезагрузку плагинов.
- **Обновление** уже импортированной сессии: дописать только то, что появилось в источнике
  после импорта, сохранив id, имя и ваши собственные ходы.
- **Восстановление отметки объёма** (watermark) без удаления и без переимпорта: копия
  доказывается по наибольшему совпадающему префиксу истории.
- **Безопасный переимпорт**: по умолчанию создаётся **новая** копия, старая **архивируется**
  (данные сохраняются, закрывать сессию не нужно).
- **Привязка к проекту** («Привязать к проекту») для сессий, попавших в Ungrouped.
- **Ассеты:** скилы → `~/.dsh/skills`; MCP-серверы → `- insert:`-блок в патч профиля **после
  бэкапа**; секреты → переменные окружения пользователя (User scope) **через временный файл с
  ACL**, никогда не в argv и не в лог; инструкции → маскированная копия для просмотра.
- **Модельные инструменты** `dsh_migrate_sessions` и `dsh_migrate_assets` — то же самое без
  интерфейса (11 и 5 действий соответственно).
- **Идемпотентность**: журналы `~/.dsh/dsh-migrate/sessions-ledger.json` и
  `assets-ledger.json`; журналы прежних плагинов читаются как **read-only фолбэк**.

## 2. Требования

| Требование | Значение |
|---|---|
| DSH | **2.x**, десктопная сборка (Electron). Браузерной версии нет; изменения применяются перезагрузкой плагинов ⟳ или перезапуском приложения |
| Node.js | 20+ (тесты — на встроенном `node --test`) |
| ОС | Windows 10/11 — основной сценарий (PowerShell-скрипты для секретов и бэкапа профиля); Linux/macOS — сессии и скилы работают, запись секретов в User-scope Windows — нет |
| Внешние зависимости | **нет** (встроенные модули Node; SQLite читается встроенным драйвером, см. `lib/sessions/sqlite.js`) |
| Сервисы хоста | `tools`, `webServer` (объявлены в `inject`); для записи сессий нужен `sessionPersistence`, для чтения — `sessionQuery`, для привязки — `workspaceRegistry` |
| Профиль DSH | запись в `<профиль>/cordis.patch.yml` **только с бэкапом**; каталог `<DSH_HOME>/dsh-migrate` создаётся автоматически |
| Права | запись в `<DSH_HOME>/skills`, `<DSH_HOME>/dsh-migrate`, патч профиля; чтение каталогов чужих агентов; `powershell` в PATH и `icacls` (для секретов) |
| Python | не требуется |

Коды возврата инструментов и маршрутов: ошибка всегда `"<КОД>: <подсказка>"`, коды —
`BAD_ARGUMENT`, `NOT_OWNER`, `CONFIRMATION_REQUIRED`, `RUN_NOT_FOUND`, `MIGRATE_FAILED`
(внутренняя ошибка выполнения).

## 3. Установка

Ставится **из репозитория `dsh-bond-plugins`** (единственный источник правды: `git pull` +
перезагрузка плагинов, без npm-реестра и zip-архивов).

### 3.1 Клонирование и установка

```powershell
git clone https://github.com/<ваш-логин>/dsh-bond-plugins.git
cd dsh-bond-plugins
powershell -NoProfile -ExecutionPolicy Bypass -File install.ps1 -Only "@local/dsh-migrate"
```

`install.ps1` делает ровно четыре шага:

1. бэкап `package.json` и `cordis.patch.yml` профиля в
   `<профиль>\backups\<ДД.ММ.ГГГГ>-<ЧЧММСС>`;
2. `dependencies` профиля: `"@local/dsh-migrate": "link:<путь-к-репозиторию>/dsh-migrate"`;
3. `dsh.profile.bundles` += `@local/dsh-migrate`;
4. `pnpm install` (junction-ссылки в `node_modules` профиля).

Варианты: `-WhatIf`, `-ProfileDir "<путь-к-профилю>"`, `-SkipInstall`.

### 3.2 Применение изменений

| Что изменилось | Как применить |
|---|---|
| `client.js`, локали, стили | **перезагрузка плагинов ⟳** |
| `index.js`, `lib/*`, маршруты, инструменты | **перезапуск DSH** |
| и то и другое | перезапуск DSH |

Плагин **сам не перезапускает DSH** и не вызывает `/dsh-reload/reload`: это оборвало бы
текущие ходы сессий. Новые MCP-строки и переменные окружения применяются перезапуском DSH.

### 3.3 Проверка, что плагин встал

- в левой полосе появился значок **«Миграция»**;
- в шапке сессии есть кнопка **«Импорт агентов»**;
- в правом доке открывается вкладка **«Миграция»**;
- панель показывает вкладки **«Сессии»** и **«Ассеты»**;
- инструмент `dsh_migrate_sessions({action:"scan"})` отвечает списком источников.

### 3.4 Откат

Скопировать `package.json` и `cordis.patch.yml` из `<профиль>\backups\<метка>` обратно,
выполнить `pnpm install`, перезапустить DSH. MCP-строки, добавленные плагином, удаляются из
патча профиля вручную (бэкап содержит состояние «до»); скилы — удалением каталогов из
`~/.dsh/skills`; переменные окружения — через «Переменные среды» Windows.

## 4. Как пользоваться

### 4.1 Открытие панели

1. Левая полоса — значок **«Миграция»**; либо кнопка **«Импорт агентов»** в шапке чата; либо
   вкладка **«Миграция»** в правом доке.
2. В шапке панели — переключатель **«Сессии» / «Ассеты»** (тот же переключатель есть в правом
   доке). Активная вкладка запоминается в `localStorage` (ключ `dsh-migrate.tab`).
3. Обе вкладки работают независимо: сессии импортируются, ассеты копируются, секреты
   пишутся только после явного подтверждения.

### 4.2 Вкладка «Сессии»

Дерево: **проект → сессии**. У проекта — счётчики («N сессий», «N уже импортировано»,
«+N субагентных»), у сессии — источник, имя, размер и признак «уже импортирована».

**Шапка вкладки и фильтры**

| Элемент | Что делает |
|---|---|
| **«Обновить»** (шапка) | перезапрашивает дерево с обходом кэша Host: `GET /dsh-migrate/sessions/tree?fresh=1`. На время запроса — спиннер и подпись «Обновление…», после ответа дерево заменяется |
| **«Обновлено: ДД.ММ.ГГГГ ЧЧ:ММ:СС»** | время последнего успешного обновления; меняется после каждого обновления (до первого — «Обновлено: —») |
| поиск | по имени сессии и пути проекта |
| фильтр источников | «Все источники» или конкретный агент |
| **«Субагентные: скрыты / показаны»** | показывать ли сессии, порождённые внутри других сессий |
| **«Контекст субагентных»** | при импорте добавить в конец сессии содержимое её субагентных сессий отдельными ходами с пометкой |

> **Важно про две кнопки с одним словом.** «Обновить» в шапке — это **перечитать дерево**
> (refresh). «Обновить» на строке уже импортированной сессии — это **дописать новое из
> источника** (update). Это разные операции с разными последствиями.

**Кнопки выбора и импорта**

| Кнопка | Что делает |
|---|---|
| галочки | каскадные: проект целиком → все его сессии; группа/сессия — независимо. По умолчанию не отмечено ничего |
| **«Импортировать проект (N)»** | импортирует все сессии проекта одним прогоном |
| **«Выбрать все видимые»** | отмечает всё, что сейчас видно с учётом фильтров и поиска |
| **«Импортировать выбранное (N)»** | импортирует отмеченное (до 50 сессий за прогон) |
| **«Снять выбор»** | сбрасывает все галочки |

**Кнопки строки сессии**

| Кнопка | Когда есть | Что делает |
|---|---|---|
| **«Обновить»** | сессия уже импортирована | `POST /dsh-migrate/sessions/update` — дописать только новое. Статусы: `updated` (дописано), `up-to-date` (источник не менялся), `busy` (в сессии открыт ход), `diverged` (источник переписал начало), `needs-reimport` (у копии нет отметки объёма) |
| **«Открыть»** | сессия уже импортирована | открывает импортированную сессию DSH |
| **«Восстановить отметку»** | строка с `needs-reimport` | `POST /dsh-migrate/sessions/repair-watermark` — **доказывает** соответствие копии источнику и проставляет отметку объёма. Ничего не удаляет и не импортирует заново |
| **«Переимпортировать»** | строка с `needs-reimport` или `diverged` | `POST /dsh-migrate/sessions/reimport` с `mode: copy` — создаёт **новую копию**, старую **архивирует** |
| **«Привязать к проекту»** | сессия не в проекте (Ungrouped) | `POST /dsh-migrate/sessions/attach` — привязывает к проекту на живую, без перезапуска; идемпотентно (`attached` / `already` / `failed`) |

**Разница трёх «исправлений» — то, что важно понимать**

| Операция | Что происходит с прежней копией | Что происходит с ledger | Когда применять |
|---|---|---|---|
| **Обновить** | остаётся той же сессией, к ней дописывается хвост | отметка объёма сдвигается | источник вырос, история не переписана |
| **Восстановить отметку** | ничего: копия та же, только получает доказанную отметку | появляются `foreignMessageCount` и `foreignPrefixHash`; при удачном доказательстве «Обновить» сразу повторяется автоматически | ledger создан прежней установкой, полей отметки нет |
| **Переимпортировать** | **новая** сессия под новым id; старая **архивируется** (скрывается из активного списка, данные сохраняются) | строка переезжает на новую копию с отметками | источник переписал историю (`diverged`) или доказать префикс нельзя |

Если доказательства нет (`diverged`) — отметка **не** проставляется: иначе история могла бы
задвоиться. Разрушающий путь (`mode: replace`, удаление старой копии) существует только как
явная опция API с `confirm: true` и только для закрытой сессии; **в панели он не
предлагается**.

**Что делает «Обновить», когда дописать нельзя.** Кнопка не упирается в тупик:

1. если у записи нет отметки объёма, плагин сначала **пытается её доказать** (`watermark`);
   доказательство удалось — обычное дописывание продолжается, владельцу ничего нажимать не
   нужно;
2. если доказать нельзя, но **копия нетронута** (число ходов в ней совпадает с тем, что записал
   импортёр, — вы в ней не работали), «Обновить» **сама пересобирает копию** в режиме `copy`:
   новый id, прежняя копия в архив, `status: updated`, `rebuilt: true`;
3. если в копии **есть ваши ходы**, автоматическая пересборка небезопасна — строка получает
   `needs-reimport` (нет отметки) или `diverged` (источник переписан) и две кнопки:
   «Восстановить отметку» и «Переимпортировать».

**Живой прогресс импорта.** «Импорт проекта» и «Импортировать выбранное» запускают на Host
прогон, за которым панель следит опросом `GET /dsh-migrate/sessions/run-status` (интервал
400 мс, параметр `?run=<id>`; без параметра — последний прогон). Показывается:

- общий процент и счётчик «i из N»;
- этап каждой сессии: `чтение источника → сборка событий → создание сессии → запись событий
  (N из M) → верификация → готово` (плюс `уже импортирована`, `пропущено`, `ошибка`);
- журнал строк: имя сессии, статус, число сообщений/ходов, предупреждения;
- итог: импортировано / переимпортировано / уже было / ошибок и «в проект X импортировано N
  сессий»;
- подсказка: **«Сессии появятся в списке после перезагрузки плагинов (⟳) или перезапуска
  DSH.»**

### 4.3 Вкладка «Ассеты»

Дерево: **источник → тип → элемент**. Типы: **Скилы**, **MCP-серверы**, **Секреты**,
**Плагины**, **Инструкции и конфиги**.

**Шапка и дерево**

| Элемент | Что делает |
|---|---|
| **«Обновить»** + подпись «Обновлено: …» | перечитывает инвентарь (`GET /dsh-migrate/assets/tree`); спиннер на время запроса |
| поиск | по имени, пути и описанию элемента |
| галочки | каскадные: источник → тип → группа → элемент. По умолчанию ничего не отмечено |
| **«Выбрать все» / «Снять всё»** | массовый выбор / сброс |
| **«Просмотр YAML»** | `POST /dsh-migrate/assets/preview` — показывает точный фрагмент для `cordis.patch.yml`, который был бы добавлен, и **имена** переменных, которые были бы записаны. Ничего не пишет |
| **«YAML»** у одного MCP-сервера | предпросмотр только этого сервера |
| **«Показать»** у инструкции/конфига | `GET /dsh-migrate/assets/instruction` — документ с **маскированными** секретами |
| чекбокс **«перезаписать уже заданные»** (в группе «Секреты») | без него переменные со статусом «уже задана» не трогаются; с ним их значения заменяются значениями из источников (запрос уходит с `overwriteSecrets=1`) |
| **«Импортировать выбранное (N)»** | `POST /dsh-migrate/assets/run` — выполняет импорт отмеченного (пакетами по 8 элементов; MCP-элементы едут вместе) |

**Статусы элементов**

| Статус | Значение |
|---|---|
| `новый` | будет импортирован |
| `обновит` | у скила в DSH более старая копия — будет заменён (с бэкапом прежней) |
| `уже есть` | цель уже существует, импорт не нужен |
| `уже читается` | скил уже виден DSH из общего корня `~/.agents/skills` — копирование только затенило бы его |
| `дубль` | то же имя уже занято другим источником в этом же прогоне |
| `не годится` | элемент не может быть импортирован (битый/недопустимый) |
| `просмотр` | конфиг чужого агента — только просмотр, не переносится |
| `только рантайм` | плагин: рантайм не переносится, переносятся его скилы и MCP-записи |
| `уже задана` / `пустая` / `конфликт` | секрет уже есть в User-scope / значения нет / в разных источниках разные значения — нужен ручной разбор |

**Диалог подтверждения.** Перед записью секретов панель спрашивает явно («Импорт изменит
переменные окружения пользователя Windows») с числом переменных и числом перезаписываемых;
значения в браузер не попадают — только имена, источники и длины.

**Отчёт импорта.** Сводка (`скопировано / обновлено / MCP добавлено / секретов записано /
пропущено / ошибок`), путь патча профиля и **путь бэкапа** (или «Бэкап не создавался — записи
не было»), блок «Переменные окружения пользователя (User scope)» (сколько записано, сколько
ошибок, удалён ли временный файл, состояние ACL, результат проверки по списку User-scope),
фрагмент YAML при добавлении MCP и напоминание: **«Чтобы новые MCP-серверы заработали, нужен
перезапуск DSH. Плагин его не выполняет, чтобы не оборвать текущие ходы сессий.»**

**Куда поедет** (подвал вкладки): скилы → `<DSH_HOME>/skills`; MCP → `<профиль>/cordis.patch.yml`;
инструкции → `<DSH_HOME>/dsh-migrate/instructions`; секреты → переменные окружения
пользователя; отдельной строкой — что `~/.agents/skills` DSH читает сам и импорт не нужен.

### 4.4 Инструменты для модели

**`dsh_migrate_sessions`** — действия:

| Действие | Что делает |
|---|---|
| `scan` | список сессий по источникам + счётчики ledger (`limit`, `offset`, `source`) |
| `search` | поиск по имени и пути проекта (`query`) |
| `import` | импорт одной сессии (`source`, `id`, `path?`, `force?`) |
| `update` | дописать новое в уже импортированную |
| `reimport` | переимпорт (`mode: copy` по умолчанию, `replace` — разрушающий) |
| `attach` | привязать к проекту (`sessionIds`) |
| `repair_watermark` | доказать копию и проставить отметку (`sessionIds` / `entryIds`, пусто — все строки без отметки) |
| `verify` | прочитать импортированную сессию слоем запросов DSH (`sessionId`) |
| `continue` | продолжить импортированную сессию одним промптом (**тратит запрос модели**) |
| `ledger` | что уже импортировано |
| `ui` | дошла ли клиентская половина до манифеста клиентских модулей |

**`dsh_migrate_assets`** — действия: `tree`, `preview`, `run`, `status`,
`read_instruction` (документ с маскированием секретов).

### 4.5 Маршруты Host (все под `/dsh-migrate/`)

Все запросы — same-origin, иначе `403 NOT_OWNER`.

| Метод | Маршрут | Назначение |
|---|---|---|
| GET | `/dsh-migrate/sessions/tree` | дерево «проект → сессии» (`query`, `source`, `perProject`, `perSourceLimit`, `includeChildren=1`, `fresh=1`) |
| POST | `/dsh-migrate/sessions/run` | пакетный импорт `{items:[{source,id,path?}], includeSubagents}` → `{runId}`; `?wait=1` — дождаться итога в одном ответе |
| GET | `/dsh-migrate/sessions/run-status` | живой прогресс прогона (`?run=<id>`; без параметра — последний) |
| POST | `/dsh-migrate/sessions/import` | импорт одной сессии (тоже прогон с прогрессом) |
| POST | `/dsh-migrate/sessions/update` | дописать новое; тупики возвращают `action: reimport` |
| POST | `/dsh-migrate/sessions/reimport` | переимпорт: `mode: copy` (по умолчанию) или `replace` + `confirm: true` |
| POST | `/dsh-migrate/sessions/repair-watermark` | доказать копию по префиксу (`{sessionIds?}`, `{entryIds?}`, `{refs?}`; пусто — все строки без отметки) |
| POST | `/dsh-migrate/sessions/attach` | привязка к проекту (`{sessionIds:[…]}`, 1…200) → `{items, summary}` |
| GET | `/dsh-migrate/sessions/status` | ledger + состояние клиентской половины + последний прогон |
| GET | `/dsh-migrate/assets/tree` | дерево «источник → тип → элемент» (`overwriteSecrets=1`) |
| POST | `/dsh-migrate/assets/preview` | предпросмотр изменений — ничего не пишет |
| POST | `/dsh-migrate/assets/run` | импорт выбранного (`dryRun`, `overwriteSecrets`) |
| GET | `/dsh-migrate/assets/status` | ledger, патч профиля, цели |
| GET | `/dsh-migrate/assets/instruction` | один документ инструкции с маскированием секретов |

│   plugins (только инвентарь), ledger

Импорт сессии идёт **тем же слоем**, что и обычные сессии DSH (холодный V4-артефакт через
`sessionPersistence`), поэтому импортированная сессия открывается и продолжается штатным
резюмом. Каждый лог проверяется на V4-инварианты **до** записи и перечитывается **после**.

## 7. Ограничения и известные особенности

1. **Плагин не перезапускает DSH** и не вызывает `/dsh-reload/reload`: это оборвало бы
   текущие ходы. Новые MCP-строки и переменные окружения владелец применяет перезапуском сам:
   другого способа применить изменения в десктопном приложении нет.
2. **Чужие каталоги агентов открываются только на чтение.** Плагин ничего не пишет и не
   правит в `~/.claude`, `~/.codex`, `~/.zcode`, `~/.kilocode`, `~/.config/opencode`,
   `~/.agents`.
3. **Рантайм плагинов чужих агентов не переносится** — только их скилы и MCP-записи. Поэтому
   группа «Плагины» информационная (`только рантайм`).
4. **Инструкции не применяются автоматически**: в `<DSH_HOME>/dsh-migrate/instructions`
   кладётся маскированная копия **для просмотра**, а не глобальный `~/.dsh/AGENTS.md`.
   Конфиги (`settings.json`, `config.toml`, `opencode.json`) — только просмотр.
5. **Секреты** записываются в переменные окружения пользователя Windows (User scope). В
   Linux/macOS-сборке этот шаг не работает; значения никогда не показываются, не логируются и
   не попадают в argv.
6. **MCP-запись требует работающего скрипта бэкапа.** Если скрипт не найден или вернул ошибку,
   запись в патч профиля **отменяется** (сообщение «резервная копия профиля не создана —
   запись отменена»). Скрипт по умолчанию лежит в самом пакете
   (`<пакет>/scripts/backup-profile.ps1`) и переопределяется `DSH_ASSETS_BACKUP_SCRIPT`.
   **Особенность:** каталог `scripts/` не перечислен в поле `files` в `package.json` — при
   установке ссылкой (`link:`, как это делает `install.ps1`) всё работает, но при упаковке
   пакета в тарбол скрипт в него не попадёт, и запись MCP будет отменяться.
7. **Отметка объёма — доказательство, а не догадка.** Если начало истории источника не
   совпало с копией (компакция, правка, «переписано»), отметка не проставляется: это
   `diverged`, и предлагается переимпорт. Иначе история задвоилась бы.
8. **Переимпорт по умолчанию не разрушает**: новая копия + архив старой. Если старую не
   удалось архивировать (например, она выполняется), отчёт скажет «старая копия осталась в
   списке», но новая копия будет создана.
9. **Обновление не трогает ваши ходы и ваше имя.** Хвост дописывается после ваших сообщений;
   имя синхронизируется с источником только если вы его не переименовывали.
10. **`busy`** — сессия сейчас выполняется (или прервана с открытым ходом): обновление
    вернёт `busy`, переимпорт копией при этом возможен (ничего не удаляется).
11. **Привязка к проекту** нужна потому, что группировка определяется реестром воркспейсов, а
    не только `cwd`: сессия, импортированная до автопривязки, может оказаться в Ungrouped.
12. **Прогресс прогона живёт в памяти Host**: перезапуск посреди импорта теряет отчёт (сам
    импорт либо лёг в хранилище, либо нет).
13. **Субагентный контекст** ограничен (50 транскриптов / 400 сообщений на ребёнка / 5000
    суммарно); лишнее отбрасывается с пометкой в отчёте. Подсказка в интерфейсе говорит «до
    10» — это расхождение текста с фактическим лимитом кода.
14. **В каталоге пакета остались служебные артефакты разработки**: `lib/sessions/import.js.bak-30.10.2026-171219`
    (резервная копия перед правкой) — на работу не влияет, при желании удаляется вручную.
15. **Дата в интерфейсе** всегда `ДД.ММ.ГГГГ ЧЧ:ММ:СС`; ISO-формат нигде не показывается.

## 8. Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| Панели нет вообще | Host-часть не загрузилась или пакет не в `dsh.profile.bundles` | проверить `package.json` профиля, перезапустить DSH |
| Панель есть, вкладки пустые | источники не найдены по путям §5.3 | проверить, что каталоги существуют и доступны на чтение |
| Нет значка «Миграция» / кнопки в шапке | не загрузилась клиентская половина | **перезагрузка плагинов ⟳**, затем перезапуск DSH |
| **«Сессия занята»** (`busy`) | в импортированной сессии открыт ход (выполняется или прервана) | дождаться завершения, открыть сессию и завершить ход; либо переимпорт копией — он не удаляет и работает при открытой сессии |
| **«Нужна отметка объёма»** (`needs-reimport`) | ledger создан прежней установкой и не хранит `foreignMessageCount`/`foreignPrefixHash` | **«Восстановить отметку»** (ничего не удаляется); если доказать нельзя — «Переимпортировать» |
| **«Источник переписан»** (`diverged`) | компакция/правка начала истории у источника | доказать префикс нельзя → «Переимпортировать» (новая копия + архив старой) |
| `update` → `up-to-date` | в источнике нет нового | ничего не делать |
| Импорт «успешен», но сессии не видно в списке | Host-часть сессий читает список при старте | **перезагрузка плагинов ⟳**; если не помогло — перезапуск DSH. Инструмент `verify` покажет `listed` |
| Сессия в **Ungrouped** | реестр воркспейсов не содержит её | «Привязать к проекту» (идемпотентно) |
| `403 NOT_OWNER` | запрос пришёл не из GUI DSH (чужой origin) | обращаться из интерфейса/инструмента DSH |
| `CONFIRMATION_REQUIRED` | `mode: replace` без `confirm: true` | либо `confirm: true` после согласия владельца, либо `mode: copy` |
| `RUN_NOT_FOUND` | опрашивается неизвестный/истёкший прогон (в памяти 25 последних) | запустить импорт заново |
| MCP: «резервная копия профиля не создана — запись отменена» | скрипт бэкапа не найден/упал, либо профиль недоступен | проверить путь (`DSH_ASSETS_BACKUP_SCRIPT`), запустить скрипт вручную, повторить |
| MCP: сервер «уже настроен» | имя уже есть в патче профиля | ничего не делать — дубль не создаётся |
| Секреты: «уже задана» и не пишутся | переменная уже существует в User-scope | включить «перезаписать уже заданные» |
| Секреты: «конфликт» | в разных источниках разные значения | разобрать вручную, оставить один источник |
| Секреты: ошибка PowerShell/ACL | нет прав, нет `icacls`, политика ExecutionPolicy | проверить права пользователя, запустить DSH под своим аккаунтом |
| Скил «уже читается» и не копируется | DSH уже видит его из `~/.agents/skills` | ничего не делать: копия только затенила бы рабочую версию |
| В отчёте «старая копия осталась в списке» | архивация не удалась (сессия выполняется) | закрыть сессию и архивировать вручную; **данные сохранены** |

**Первые шаги диагностики:** `dsh_migrate_sessions({action:"ui"})` — дошла ли клиентская
половина до манифеста; `dsh_migrate_sessions({action:"verify", sessionId})` — читается ли
импортированная сессия и видна ли она в списке; `GET /dsh-migrate/sessions/status` — ledger,
состояние UI и последний прогон целиком.

## 9. Безопасность

**Что плагин читает**

- каталоги чужих агентов (`~/.claude`, `~/.codex`, `~/.zcode`, `~/.kilocode`,
  `~/.config/opencode`, `~/.agents`) — сессии, скилы, MCP-записи, инструкции, конфиги;
- `<профиль>/cordis.patch.yml` — чтобы понять, какие MCP уже настроены;
- артефакты сессий DSH через `sessionQuery` / `sessionPersistence` — для верификации,
  обновления и доказательства отметки;
- **секреты** — значения читаются в память процесса и сразу передаются в `envwriter`;
  наружу отдаются только **имя, источник и длина**.

**Что плагин пишет**

- `<DSH_HOME>/dsh-migrate/*.json` — журналы идемпотентности;
- `<DSH_HOME>/dsh-migrate/instructions/*` — маскированные копии инструкций;
- `<DSH_HOME>/skills/<имя>/` — скилы (прежняя копия при обновлении сохраняется как бэкап);
- `<профиль>/cordis.patch.yml` — `- insert:`-блок MCP **только после успешного бэкапа**,
  атомарно (`.tmp` + `rename`);
- переменные окружения пользователя Windows (User scope) — через временный каталог с ACL
  только для текущего пользователя, файл `payload.json` (режим 0600), `set-user-env.ps1`,
  затем каталог удаляется и результат проверяется повторным чтением списка имён;
- артефакты новых сессий — через `sessionPersistence` (штатный слой DSH);
- архивную метку старой копии при переимпорте.

**Чего плагин не делает**

- не пишет в чужие каталоги агентов и не меняет их конфигурацию;
- не показывает, не логирует и не передаёт в браузер значения секретов;
- не передаёт значения в argv (никакого `setx`: он ещё и обрезает длинные значения);
- не перезапускает DSH и не вызывает `/dsh-reload/reload`;
- не удаляет сессии без явного `mode: replace` + `confirm: true`;
- не правит `~/.dsh/AGENTS.md` и не применяет чужие инструкции автоматически.

**Границы доверия**

- same-origin guard (`sec-fetch-site`) защищает маршруты от чужой вкладки браузера — это не
  аутентификация;
- имена элементов проверяются **повторным сканированием источников**: клиент присылает
  `{type, source, name}`, а путь резолвится заново, поэтому подделанный запрос не заставит
  плагин читать/писать вне обнаруженных путей;
- `DELETE`-подобная операция (`rm -rf` каталога сессии) выполняется только в разрушающем
  переимпорте, только для закрытой сессии и только с подтверждением;
- **плагин исполняет код в процессе DSH** — ставить только из доверенного репозитория.
