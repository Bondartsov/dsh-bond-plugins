## 2. Причины (три независимых дефекта, каждый достаточен)

### Причина A — не требовалось доказательство владения

`unimportSession` искал запись в журнале, но не проверял результат:

```js
const entry = listImports().find((row) => row.sessionId === sessionId);
// ...нет проверки entry !== undefined
await calm(workspace.archiveSession(sessionId, {}));   // ← архивируется ЛЮБАЯ сессия
renameSync(dir, target);                                // ← переносится ЛЮБОЙ артефакт
```

Строки 43, 51–52, 71 версии 1.0.5. Под условием `if (entry !== undefined)` стояла только
`forgetImport`. Итог: любой переданный `sessionId` — включая чужие сессии — архивировался и уезжал в карантин.

### Причина B — порядок операций терял единственную защиту

Было: **сначала** `forgetImport` (строка 60), **потом** перенос файла (строка 71).
Первый вызов удалил из журнала записи 523 копий; второй вызов работал уже с пустым журналом и,
из-за причины A, уносил всё, что ему передали. Один дефект усилил другой.

### Причина C — список для массовой операции строился по mtime, а не по журналу

Мой скрипт отбирал артефакты по `LastWriteTime` файла в окне sweep. Активные сессии владельца
(в том числе текущая) писались именно в этом окне и попали в список. Журнал импорта — единственный
законный источник идентичностей — не использовался.

### Дополнительный фактор — отсутствие предела батча

Один вызов принимал до 2000 id и применял их без проверки плана и без подтверждения.

## 3. Что сделано, чтобы это не повторилось

| Мера | Где | Сторож-тест |
|---|---|---|
| **A. Гейт владения**: нет записи в журнале → `status: "refused"`, ноль записей на диск | `unimport.js`, до любых действий | «сессия вне журнала — отказ, архив не вызван, артефакт на месте» |
| **B. Безопасный порядок**: файл → карантин, затем забыть запись, затем архивация | `unimport.js` | «артефакт покидает store раньше, чем забывается журнал» |
| **C. Манифест карантина**: `projectFolder`, `source`, `foreignId`, `title`, `movedAt` | `unimport.js` | восстановление по манифесту (`restoreQuarantine`) |
| **D. Предел батча** `MAX_BATCH = 50`, больше — только с `confirm: true` | `unimport.js` + маршрут | «массовое удаление без confirm отклоняется» |
| **E. Восстановление** `POST /dsh-migrate/sessions/restore-quarantine` | `index.js`, `unimport.js` | dry-run восстанавливает план |
| **F. `replace`-переимпорт больше не удаляет**: перенос в `quarantine/replace-<ts>/` | `reimport.js` | существующие тесты replace + набор 187/187 |

## 5. Процессные правила, принятые после разбора

1. Деструктивные операции (`unimport`, `reimport mode=replace`, любые массовые действия с файлами)
   на живом профиле — только по прямому указанию владельца, сначала `dryRun`, затем одно действие.
2. Никогда не формировать список массовой операции по времени изменения файлов — только по журналу
   импорта.
3. Массовый импорт не запускается без выбора владельца (запрет 06.11.2026).
4. Карантин — не мусор и не удаляется; восстановление идёт по манифестам.
