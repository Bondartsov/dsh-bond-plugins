# ТЗ: единый плагин миграции `@local/dsh-migrate` (две вкладки) + правки UI

Дата: 29.10.2026
Заказчик: владелец DSH (через Lead-сессию 24b76a)
Приоритет: высокий — владелец хочет **один** плагин миграции с вкладками, а не два

## 1. Задача

Собрать **один** плагин `@local/dsh-migrate`, внутри которого две вкладки:

1. **«Сессии»** — то, что сейчас делает `@local/dsh-agent-import` (импорт сессий из Claude Code, Codex, ZCode (v1/v2), KiloCode, OpenCode: дерево «проект → сессии», каскадные галочки, «Импорт проекта», «Select all visible», «Обновить»/«Открыть», скрытие субагентных сессий с опцией «контекст субагентных», ledger идемпотентности).
2. **«Ассеты»** — то, что сейчас делает `@local/dsh-assets-import` (скилы, MCP, плагины, инструкции, **секреты**; чекбоксы, статусы «новый/уже есть/обновит/уже читается/дубль/конфликт», предпросмотр YAML для MCP, подтверждение записи секретов в User-scope).

Источники кода для переноса (читай и переиспользуй, не переписывай с нуля):
- `<путь-к-репозиторию>\dsh-agent-import\` — Host (`index.js`, `lib/`), клиент (`client.js`), тесты.
- `<путь-к-репозиторию>\dsh-assets-import\` — Host (`index.js`, `lib/*.js`, `lib/*.ps1`), клиент, тесты.

Допустимо **скопировать** нужные файлы в новый пакет и адаптировать (так проще, чем связывать пакеты). Оба исходных пакета **не удаляй и не ломай** — они остаются рабочими, пока владелец не подтвердит новый.

## 2. Архитектура

- Один пакет `<путь-к-репозиторию>\dsh-migrate\` с `package.json` (`dsh.bundle`, `dsh.client`), `cordis.patch.yml` (`- insert: id: migrate`), `icon.svg`, `locale\{ru,en}.json`, `README.md` (рус.).
- Host: одна страница-плагин с **одним** набором маршрутов под префиксом `/dsh-migrate/`:
  `GET /dsh-migrate/sessions/tree`, `POST /dsh-migrate/sessions/run`, `GET /dsh-migrate/sessions/status`,
  `GET /dsh-migrate/assets/tree`, `POST /dsh-migrate/assets/run`, `POST /dsh-migrate/assets/preview`, `GET /dsh-migrate/assets/status`.
  Внутри — вызовы скопированной логики из `lib/` (сессии и ассеты как два независимых слоя).
- Клиент: **одна** панель с двумя вкладками (`Сессии` / `Ассеты`), каждая со своим деревом и кнопками.
  Тот же переключатель вкладок дублируется в шапке страницы; активная вкладка запоминается в localStorage.
- Точки входа: главная страница плагина + значок в левой полосе + вкладка правой стойки (как у существующих).
- Правила сохранения: ledger'ы идемпотентности — общие по типам (`~/.dsh/dsh-migrate/*.json`), формат журнала не ломать.

## 3. Правки UI (из замечаний владельца)

1. **Кнопка «Refresh» на вкладке сессий**: проверить, что она реально перезапрашивает дерево (сейчас владелец не уверен). При нажатии — спиннер/«Обновление…», после — новое дерево.
2. **Подпись «когда обновлено»** — под кнопкой Refresh (или строкой в шапке): «Обновлено: ДД.ММ.ГГГГ ЧЧ:ММ:СС». После обновления — обновлять подпись. Формат даты строго РФ.
3. **Стрелки раскрытия групп** (скилы/сессии/проекты) — сейчас маленькие и незаметные: сделать крупнее (иконка ≥ 16 px, зона нажатия ≥ 24×24 px, цвет `--dsw-alias-label-secondary`, при наведении — `--dsw-alias-label-primary`), чтобы было очевидно, что дерево разворачивается. То же для вкладки «Ассеты».
4. Ничего не отмечать по умолчанию (как сейчас).

## 4. Приёмка

1. Открывается **одна** страница с двумя вкладками; обе работают независимо (сессии импортируются, ассеты копируются, секреты пишутся с подтверждением).
2. Refresh перезапрашивает данные и обновляет подпись времени (проверить: изменить состояние источника → Refresh → дерево изменилось).
3. Стрелки раскрытия визуально крупнее, зона нажатия ≥24 px (проверить в реальном рендере).
4. Даты — только `ДД.ММ.ГГГГ ЧЧ:ММ:СС`.
5. Тесты: `node --test "test/*.test.mjs"` — зелёные; включить тесты маршрутов, «секреты не утекают», идемпотентность обоих слоёв.
6. Старые плагины (`dsh-agent-import`, `dsh-assets-import`) не тронуты и продолжают работать.

## 5. Ограничения

- Профиль: добавление нового бандла/линка — **только** своим путём и с бэкапом (`package.json` + `cordis.patch.yml`), бэкап-скрипт: `<путь-к-репозиторию>\profile-backups\backup-profile.ps1`.
- **Не запускай** `/dsh-reload/reload` и перезапуск DSH — обрывает ходы сессий; скажешь владельцу, когда нужен старт.
- После ЛЮБОГО `install_bundle`/`remove_bundle` — сначала проверить, что `@deepseek-ai/dsh-tool-cordis` и `@deepseek-ai/dsh-plugin-manager` на месте (`CC9A565E07EA` / `53ED83FEB2A4`), и только если пропали — `core-overrides\restore-overrides.ps1`.
- Секреты: значения не показывать, не логировать, не помещать в argv; правила из `dsh-assets-import\lib\envwriter.js` сохранить без изменений.
- Чужие каталоги — только чтение.
