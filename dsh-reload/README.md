# dsh-reload — панель «Reload DSH»

`@local/dsh-reload` добавляет в левую панель строку **Reload DSH**, которая
открывает страницу с двумя действиями: **перезагрузить плагины** (профиль
собирается заново, приложение остаётся открытым) и **перезапустить DSH полностью**
(новый процесс Host и новое окно). Под карточками — `pid` и время старта текущего
процесса Host.

## 1. Что это и какую задачу решает

При разработке плагина цикл «правка → применить» обычно означает «закрыть и
открыть приложение». Панель сокращает его:

- **⟳ перезагрузка плагинов** — Host заново собирает профиль из манифеста и
  patch-файлов, перезапускает записи Loader, чьи файлы изменились на диске
  (включая linked-пакеты вида `link:<путь-к-репозиторию>/<плагин>`), повторяет
  импорт упавших записей, после чего страница перезагружается и клиентские
  бандлы собираются заново;
- **полный перезапуск** — когда изменение кэшируется на время жизни процесса и
  никакой reconcile его не подхватит (пример: вердикт «пакет не клиентский» у
  `@deepseek-ai/dsh-client-modules` запоминается на всю жизнь Host, поэтому
  добавленная секция `dsh.client` у уже установленного пакета не попадёт в
  `window.__DSH_BOOT__` без нового процесса).

Плагин же даёт то, чего нет в интерфейсе DSH: состояние процесса (`pid`, время
старта) и результат действий прямо на странице, без модальных окон.

## 2. Требования

- **DeepSeek Harness 2.x**, десктопная сборка (Electron) либо CLI `dsh web`.
- Host-сервисы: `webServer` (объявлен в `inject` — без него маршруты не
  регистрируются), `hmr` с `reconcileProfile` и `runExclusive` — для ⟳,
  `agents` и `sessions` — для аккуратного перезапуска (необязательны: их
  отсутствие деградирует, а не ломает).
- Windows: `tasklist`, `taskkill` — для перезапуска. Запуск helper'а пробует
  `wmic`, `schtasks`, `explorer`, затем обычный дочерний процесс.
- Node.js 20+ и pnpm 9+ — только для установки из репозитория.

## 3. Установка из репозитория `dsh-bond-plugins`

```powershell
git clone https://github.com/<ваш-логин>/dsh-bond-plugins.git
cd dsh-bond-plugins
powershell -NoProfile -ExecutionPolicy Bypass -File install.ps1
```

Только этот плагин:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File install.ps1 -Only "@local/dsh-reload"
```

План без изменений: `install.ps1 -WhatIf`. Нестандартный профиль:
`-ProfileDir "<путь-к-профилю>"`.

Скрипт снимает резервную копию `package.json` и `cordis.patch.yml` профиля в
`<профиль>\backups\<ДД.ММ.ГГГГ>-<ЧЧММСС>`, добавляет пакет в `dependencies` как
`link:`, добавляет его в `dsh.profile.bundles` и запускает `pnpm install`.

После установки нужен **полный перезапуск DSH**: у плагина есть Host-половина
(маршруты и перезапуск), а ⟳ — это и есть кнопка этого плагина, которой ещё нет.
Если плагин ставится в уже работающее приложение, перезапустите его вручную
(закрыть окно и открыть DSH снова). Дальше ⟳ уже доступна в интерфейсе.

## 4. Как пользоваться

1. В левой панели появляется строка **Reload DSH** со значком круговой стрелки
   (в списке панелей она зарегистрирована с порядком 30).
2. Клик открывает страницу **Reload DSH** с подзаголовком «Применить изменения
   плагинов или поднять новый процесс Host».
3. Две карточки:
   - **«Перезагрузить плагины»** (основная кнопка) — описание: профиль
     собирается заново, плагины с изменёнными файлами перезапускаются, упавшие
     импорты повторяются, страница обновляется, приложение остаётся открытым;
   - **«Перезапустить DSH полностью»** (кнопка-danger) — описание: новый процесс
     Host и приложения, окно закроется и откроется заново через несколько секунд.
4. Ниже — строка состояния: зелёная точка, `PID процесса: <pid>`, `запущен
   ДД.ММ.ГГГГ ЧЧ:ММ:СС`. Если маршрут состояния недоступен, вместо неё —
   «Состояние процесса недоступно» и причина в скобках; строка не блокирует
   кнопки.
5. Результат показывается **на этой же странице**, под карточками:

| Что видно | Что означает |
|---|---|
| тихая перезагрузка страницы | всё применено, ждать нечего |
| жёлтый блок «Нужен полный перезапуск приложения» | часть модулей загрузится только новым процессом; в списке — причина (`Изменён модуль самого Хоста`, `Пакет плагина переехал на другой путь`, `Плагин загружен не из профиля`, `Модуль изменился и требует нового процесса`), число модулей до перезапуска и предупреждений профиля; кнопки «Скрыть» и «Перезагрузить страницу» |
| красный блок «Не удалось» + текст ошибки | Host вернул ошибку: обычно опечатка или исключение в плагине, который перезагружался; кнопка «Скрыть» |
| жёлтый блок «Сейчас идёт работа агента» | перезапуск отклонён (HTTP 409): показано число активных ходов; кнопки «Отмена» и «Всё равно перезапустить» (последняя отправляет `force: true`) |
| блок «Перезапускаюсь…» | Host принял запрос (HTTP 202): процесс `pid` завершается, окно вернётся само; если через минуту окна нет — запустите DeepSeek Harness вручную |

6. Во время выполнения кнопки показывают «Перезагружаю…» / «Перезапускаю…» и
   заблокированы — повторный клик невозможен.

### Когда кнопку ⟳ нажимать НЕ надо

- **Правился только Host-код плагина, который сейчас выполняет ход агента.**
  reconcile остановит запись Loader, то есть выдернет код из-под работающего
  вызова. Дождитесь конца хода.
- **Файл ещё пишется** (редактор/скрипт не закончил сохранение): reconcile
  импортирует недописанный модуль и покажет ошибку. Сохраните файл целиком.
- **Ничего не менялось.** Перезагрузка не «освежает на всякий случай»: она
  заново собирает профиль и перезапускает изменившиеся записи.
- **Нужен новый клиентский бандл, которого не было в манифесте** (добавили
  `dsh.client` в уже установленный пакет). Это как раз случай полного перезапуска.
- **Идёт долгая операция в другом плагине** (импорт, миграция): ⟳ перезапустит
  его запись, и операция прервётся.

## 5. Настройка

Настраиваемых пользователем параметров нет: ни файла конфигурации, ни переменных
окружения, ни localStorage. Всё поведение задано константами и маршрутами.

| Параметр | Где | Значение | Смысл |
|---|---|---|---|
| `ROUTE` | `index.js` | `/dsh-reload/reload` | `POST` — reconcile профиля |
| `RESTART_ROUTE` | `index.js` | `/dsh-reload/restart` | `POST` — полный перезапуск |
| `STATUS_ROUTE` | `index.js` | `/dsh-reload/status` | `GET` — факты о процессе |
| `HEADER` | `index.js` | `x-dsh-reload: 1` | обязательный заголовок для `POST` |
| `RESTART_DELAY_MS` | `index.js` | `600` | пауза между ответом `202` и запуском helper'а |
| `HELPER_LOG` | `index.js` | `%TEMP%\dsh-reload-restart.log` | трасса helper'а, одна строка на шаг |

### Что именно перезагружает ⟳

- заново собирает профиль из `package.json`, `dsh.profile.bundles` и patch-файлов;
- находит плагины, чьи **загруженные файлы** изменились на диске, если файлы лежат
  в каталоге профиля или в целях `link:`-пакетов;
- останавливает их записи Loader, запускает снова на текущем коде;
- импортирует записи, чей импорт ранее падал;
- возвращает `{ pending, warnings, restartReason }`; клиент игнорирует причину
  `unmanaged-plugin` (общие библиотеки в `node_modules` профиля — zod,
  schemastery и т. п.: они не принадлежат плагинам и не перезапускаются by design),
  остальные причины показываются как «Нужен полный перезапуск».

Это всё выполняется под `hmr.runExclusive(...)`: reconcile — мутация,
принадлежащая вызывающему, и без сериализации с автоматическими перезагрузками
служба отказывается работать.

### Что именно перезапускает полный перезапуск

`POST /dsh-reload/restart`:

1. Если есть агенты со статусом `running` и не передан `force` — `409
   {reason: "agents-running", running: [...]}`; ничего не происходит.
2. При `force` каждому активному агенту отправляется отмена (`cancel({kind:
   "user"})` либо `interrupt`; отсутствие полномочия отмены не фатально).
3. `sessions.flush(session)` для каждой живой сессии — логи ложатся на диск.
4. Ответ `202 {ok, restarting, mode, pid, delayMs, cancelled, flushed, flushFailed}`;
   страница успевает показать «Перезапускаюсь…».
5. Через ~600 мс helper-скрипт `%TEMP%\dsh-reload-restart-<pid>.cmd` перезапускает
   приложение:
   - **desktop**: проверяет, что `ppid` действительно процесс приложения
     (`tasklist`, имя равно `basename(execPath)`), убивает дерево
     `taskkill /F /T /PID <ppid>`, ждёт исчезновения до 20 с, добивает
     осиротевший Host по своему `pid` (чтобы освободить порт) и делает
     `start "" "<execPath>"` **без аргументов** — профиль и `dsh-app://` поднимает
     сама оболочка;
   - **CLI (`dsh web`)**: ничего не убивает, ждёт выхода Host по `pid` и запускает
     тот же `execPath` с теми же аргументами; порт может смениться — сменится и URL.

`dryRun: true` в теле запроса возвращает план (режим, путь и текст скрипта,
список launcher'ов, число сессий к сбросу), ничего не запуская.

## 6. Архитектура кратко

| Половина | Файл | Роль |
|---|---|---|
| Host | `index.js` | три маршрута, `processFacts`, план перезапуска, запуск helper'а |
| Client | `client.js` | строка `sidebar.panellist` (id `dsh-reload`, order 30) + страница `main` (key `dsh-reload`), статус и карточки |

Используемые сервисы DSH:

- `ctx.webServer.register({kind: "exact", path, handler})` — маршруты; один и тот
  же origin в Web GUI (`http://127.0.0.1:<порт>`) и в десктопе, где `dsh-app://`
  пересылает неизвестные пути слушателю Host;
- `ctx.get("hmr")` → `runExclusive`, `reconcileProfile`;
- `ctx.get("agents")` → `list()` и отмена хода; `ctx.get("sessions")` → `list()`,
  `flush()`;
- слоты `sidebar.panellist` и `main`, локаль `dshReload`.

Состояние: у плагина его нет. `pid` и `startedAt` читаются из процесса
(`process.pid`, `Date.now() - process.uptime()*1000`), результат действий живёт
в React-состоянии страницы и исчезает при её перезагрузке. Единственный
долгоживущий артефакт — лог helper'а в `%TEMP%`.

Почему маршрут, а не Host Remote: обычный JS-бандл может зарегистрировать
HTTP-маршрут через `ctx.webServer` без генерации Typert `@Remote`-кода, а
страница достаёт его как same-origin.

Почему helper, а не `app.relaunch()`: Host — дочерний процесс Electron-оболочки,
запущенный в Node-режиме (`ELECTRON_RUN_AS_NODE=1`), `require("electron")` там
падает, объекта `app` нет (это видно в `GET /dsh-reload/status` →
`electronModule`).

## 7. Ограничения и типичные ошибки

- **⟳ не всесилен.** Он не перезагружает: сам Host-модуль DSH, пакеты вне профиля
  и вне целей `link:`, и всё, что кэшировано на время жизни процесса (вердикт
  «не клиентский пакет» у `@deepseek-ai/dsh-client-modules`, композиция
  `window.__DSH_BOOT__`). Признак — жёлтый блок «Нужен полный перезапуск
  приложения» либо `pending`/`restartReason` в ответе маршрута. В этом случае
  нужен полный перезапуск.

  > Замечание для владельца: README репозитория формулирует правило жёстче —
  > «⟳ не перезагружает Host-код плагинов». В текущем коде reconcile как раз
  > перезапускает изменившиеся записи Loader, включая linked-пакеты. Практическое
  > правило: смотрите на ответ — если `pending` пуст, всё применено; если нет —
  > перезапуск. Если сомневаетесь, перезапуск безопаснее.
- **Четвёртый launcher helper'а не выживает.** `wmic` → `schtasks` → `explorer` —
  внешние по отношению к дереву процессов; обычный дочерний процесс (крайний
  случай) погибает вместе с деревом, и приложение не вернётся. В лог при этом
  пишется `no out-of-tree launcher worked: …`. Если `wmic` в системе удалён
  (Windows 11), используется `schtasks`/`explorer`.
- **Окно не вернулось за минуту** — запустите DeepSeek Harness вручную: helper
  мог не найти launcher или приложение упало при старте. Смотрите
  `%TEMP%\dsh-reload-restart.log` и `%TEMP%\dsh-reload-restart-<pid>.cmd`.
- **`force` теряет недописанный ответ.** Отмена хода завершает его аккуратно, но
  недописанный текст ответа пропадёт — блок подтверждения об этом предупреждает.
- **`404` на маршрутах.** Плагин не загрузился (нет в `dsh.profile.bundles`) или
  Host стартовал раньше публикации `webServer` (лечится объявленным `inject`,
  строка уже есть). Перезапустите DSH.
- **`403` при ручном вызове** — забыт заголовок `x-dsh-reload: 1`. Без него
  маршрут недоступен и чужой веб-странице (CORS-preflight эти маршруты не
  обслуживают).
- **Порт сменился (CLI).** После перезапуска `dsh web` может выбрать другой порт —
  URL изменится. В десктопе URL фиксирован схемой `dsh-app://`.
- **Плагин сам себя не перезапускает в процессе перезапуска**: во время ⟳ его
  запись Loader тоже может быть перезапущена, страница на это время недоступна —
  это нормально, после перезагрузки страницы панель вернётся.
- **Linux/macOS**: маршруты и ⟳ работают, полный перезапуск рассчитан на Windows
  (`tasklist`/`taskkill`, `.cmd`-helper). На других ОС используйте перезапуск
  приложения вручную.

## 8. Тесты

```powershell
node --test "test/*.test.mjs"
```

Файл один — `test/restart.test.mjs`, **6 тестов**, все на моках (живой процесс не
перезапускается):

1. `409` при работающем агенте без `force`, и при отказе ничего не сливается на диск;
2. `force: true` отменяет ход, сбрасывает каждую живую сессию и отвечает `202`;
3. `dryRun` описывает план, но не сбрасывает сессии и не запускает helper;
4. запрос без заголовка-гарда отклоняется;
5. desktop-план отказывается убивать родителя, который не является приложением;
6. у CLI-Host план — «дождаться выхода и запустить снова», без `taskkill`.

Проверка на живой машине (по желанию) — `GET /dsh-reload/status` до и после
перезапуска: `pid` и `ppid` должны отличаться; `dryRun` показывает план, ничего
не делая.
