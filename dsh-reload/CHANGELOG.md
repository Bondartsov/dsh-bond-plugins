# История изменений

Формат: [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/); версии — semver.

## [1.1.0] — 31.10.2026

Проверка обновлений по плагинам: строка версии в интерфейсе, маршрут и режим `-Check`
показывают, **какие именно плагины** изменились, а не «обновлено всё».

### Добавлено

- `GET /dsh-reload/updates` — проверка обновлений плагинов: `git fetch` плюс
  сравнение `HEAD` с `origin/<ветка>`. Ответ:
  `{ok, installed, remote, behind, ahead, branch, repo, fetched, dirty, warning, changedPlugins, checkedAt}`;
  ошибки — `503 {ok: false, reason: "no-git" | "no-repo", error, hint?}`.
  Маршрут только читает: `git pull`/`merge`/`checkout` в нём нет и быть не должно —
  плагин исполняет код, поэтому обновление остаётся действием владельца.
- `changedPlugins` в ответе — какие каталоги плагинов реально изменились:
  `[{dir, name, from, to}]`, версии из `package.json` обеих ревизий.
  Считается на Host-половине: `git diff --name-only HEAD..origin/<ветка>` с
  группировкой по первому сегменту пути, список плагинов — из `plugins.json`.
  Ответ на «обновился один peer-bus» называет только его, никаких «обновлено всё».
- Параметр `?fetch=0` — версия без сети: только локальный коммит.
- Каталог репозитория определяется без личных путей: сначала `DSH_BOND_PLUGINS`,
  иначе каталог над модулем плагина (`<репозиторий>/dsh-reload/index.js`).
- Строка версии на странице «Reload DSH»: «Версия плагинов: <хеш> · проверить
  обновления» и итог проверки — «`peer-bus` 2.1.0 · обновление: 1 плагин
  (`peer-bus` 2.1.0 → 2.2.0)», «3 коммита без изменений в каталогах плагинов»,
  «обновлений нет», «удалённую версию узнать не удалось: …», «Не удалось
  проверить обновления: …».
- Сторож-тесты `test/updates.test.mjs` (16 штук): контракт ответа, запрет
  мутирующих git-команд, поведение без `git` и без репозитория, офлайн-режим,
  регистрация маршрута, отсутствие личных путей в Host-половине,
  `changedPlugins` (назван один каталог с версиями; изменения вне плагинов дают
  пустой список; актуальная копия не запрашивает `git diff`; битый
  `package.json` не роняет ответ).
- `update.ps1 -Check` (работает и как `--check`) — проверка без изменений:
  `git fetch`, таблица «плагин · версия сейчас · изменился ли каталог в
  HEAD..origin/main», итог «изменено плагинов: N из 7», версии до/после и
  коммиты этих плагинов; без pull/merge/`pnpm install`. Без сети печатает
  последнее известное состояние. Код возврата: 0 — проверка выполнена,
  1 — версии прочитать не удалось.

### Изменено

- `dsh-reload/README.md`: раздел «Проверка обновлений плагинов»,
  новые строки в таблицах маршрутов и архитектуры, ограничения про «не определена»
  и офлайн, обновлён раздел тестов.
- Корневой `README.md`: раздел «Как узнавать об обновлениях» — независимые версии
  плагинов, снапшот репозитория целиком, пример вывода для случая «изменился один
  плагин», `-Only`.

## 1.0.0 — 31.10.2026

Первый публичный релиз в составе репозитория `dsh-bond-plugins`.

### Добавлено

- Строка **Reload DSH** в левой панели (слот `sidebar.panellist`, id `dsh-reload`,
  order 30) и страница с тем же ключом `dsh-reload` в слоте `main`.
- Действие **«Перезагрузить плагины»**: `POST /dsh-reload/reload` →
  `hmr.runExclusive(() => hmr.reconcileProfile())`, затем перезагрузка страницы;
  результат (`pending`, `warnings`, `restartReason`) показывается на самой
  странице, причина `unmanaged-plugin` отфильтровывается как шум.
- Действие **«Перезапустить DSH полностью»**: `POST /dsh-reload/restart` с
  подтверждением в интерфейсе, `409 agents-running` при активных ходах и
  повтором с `force: true`, отменой ходов, сбросом логов живых сессий и ответом
  `202` до выхода процесса.
- `GET /dsh-reload/status`: `pid`, `ppid`, `execPath`, `argv`, `cwd`, версия
  Electron, `ELECTRON_RUN_AS_NODE`, результат пробы `require("electron")`,
  `DSH_PROFILE`, `startedAt`; строка состояния на странице показывает `pid` и
  время старта в формате `ДД.ММ.ГГГГ ЧЧ:ММ:СС`.
- Планировщик перезапуска: отдельный `.cmd`-helper в `%TEMP%`, режимы desktop
  (проверка родителя, `taskkill /F /T`, ожидание исчезновения PID, добивание
  осиротевшего Host, `start` без аргументов) и CLI (дождаться выхода, запустить
  тот же `execPath` с теми же аргументами).
- Запуск helper'а вне дерева процессов с деградацией:
  `wmic` → `schtasks` → `explorer` → обычный дочерний процесс (с предупреждением
  в лог, что приложение не вернётся).
- `dryRun: true` — вернуть план перезапуска (режим, путь и текст скрипта, список
  launcher'ов, число сессий к сбросу), ничего не выполняя.
- Гард-заголовок `x-dsh-reload: 1` на обоих `POST`; `403` без него, `405` для
  неверного метода.
- Объявленная зависимость `inject = ["webServer"]` — маршруты регистрируются
  после публикации службы даже на холодном старте.
- Трасса helper'а в `%TEMP%\dsh-reload-restart.log`.
- Тесты Host-половины на моках: 6 штук (`test/restart.test.mjs`).

### Ограничения релиза

- ⟳ не перезагружает то, что кэшировано на время жизни процесса (вердикт
  «не клиентский пакет», композиция `window.__DSH_BOOT__`), сам Host-модуль DSH и
  пакеты вне профиля/целей `link:` — для этих случаев есть полный перезапуск.
- Полный перезапуск реализован для Windows; на Linux/macOS работает только ⟳.
- Если ни один внешний launcher не сработал, четвёртый вариант погибает вместе с
  деревом процессов: окно не вернётся, приложение нужно запустить вручную.
- CLI-режим может сменить порт после перезапуска — URL изменится.
