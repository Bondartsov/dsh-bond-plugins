# Как участвовать

Спасибо, что заглянули. Репозиторий — коллекция плагинов для DeepSeek Harness (DSH), и он
открыт для правок: исправления, новые возможности и документация приветствуются.

## Быстрый старт

```powershell
git clone https://github.com/<логин>/dsh-bond-plugins.git
cd dsh-bond-plugins
powershell -NoProfile -ExecutionPolicy Bypass -File install.ps1
```

Затем ⟳ в интерфейсе DSH (или полный перезапуск, если менялась Host-часть плагина).

## Перед pull request

1. **Тесты зелёные.** У каждого плагина свой набор:

   ```powershell
   cd peer-bus; node --test "test/*.test.mjs"
   cd dsh-subagent-indicator; node test/run-tests.mjs
   ```

2. **Синтаксис.** `node --check index.js` и `node --check client.js` в каталоге плагина.

3. **Сторож-тест на новое поведение.** В репозитории действует правило: на каждое правило
   поведения — тест, который упадёт, если правило нарушили. Не «функция вернула число», а
   «обновление не удаляет копию сессии», «кольцо привязано к нашему атрибуту, а не к классу
   сборки».

4. **Документация обновлена.** Если изменилось поведение — правьте `README.md` и
   `docs/DESIGN.md` того же плагина, добавьте запись в `CHANGELOG.md` (группы: Добавлено /
   Изменено / Исправлено / Безопасность).

## Правила кода

| Правило | Почему |
|---|---|
| Никаких внешних зависимостей в плагинах | Плагин должен ставиться без `npm install` и не тянуть чужой код в процесс DSH |
| Никаких личных путей (`C:\Users\<имя>\…`) | Пути берутся из `DSH_PROFILE_DIR` / `USERPROFILE`; иначе плагин работает на одной машине |
| Никаких хардкод-цветов в интерфейсе | Только токены темы `--dsw-alias-*`, иначе тёмная/светлая тема ломается |
| Даты в текстах — `ДД.ММ.ГГГГ` | Так владелец читает; ISO — только там, где требует машина |
| Формулировки только десктопные | DSH — Electron-приложение: «перезагрузка плагинов ⟳» или «перезапуск DSH», никаких «обновите страницу» |
| Секреты — только в переменных окружения | В конфигурации остаются ссылки `${VAR}`, значений в репозитории быть не должно |

## Структура плагина

```
<плагин>/
├── package.json          # имя, версия, dsh.client / dsh.bundle, files
├── index.js              # Host-половина: маршруты, инструменты, сервисы DSH
├── client.js             # Client-половина: слоты интерфейса
├── cordis.patch.yml      # собственный слой конфигурации
├── locale/ru.json        # локали
├── lib/                  # внутренние модули Host-половины
├── test/                 # тесты
├── README.md             # что это и как пользоваться
├── docs/DESIGN.md        # как устроено и почему
└── CHANGELOG.md          # история изменений
```

## Коммиты

Conventional Commits, по-русски или по-английски — как удобнее, но одинаково:

```
fix(peer-bus): мастер остаётся в строке проекта, когда сессия спит
feat(dsh-migrate): переименование копии вслед за источником
docs(dsh-reload): когда ⟳ не помогает и нужен перезапуск
```

## Что не стоит присылать

- Правки, которые «упрощают» уже принятые решения без объяснения (например, возвращают
  удаление копии при переимпорте — это потеря данных).
- Код, который ставит пакеты или меняет профиль DSH при загрузке плагина.
- Секреты, токены, персональные пути и дампы чужих сессий.
