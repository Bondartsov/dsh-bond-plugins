# composer-cost — стоимость сессии в рублях

`@local/composer-cost` добавляет в полосу статистики под полем ввода композера
две ячейки: **расход текущей сессии** и **итог за сегодня** (с разбивкой за день и
неделю по наведению). Сумма считается из токенов, которые DSH уже учитывает, и
таблицы тарифов провайдера, поэтому везде стоит знак `≈` — это оценка, а не
счёт из биллинга.

## 1. Что это и какую задачу решает

DSH знает, сколько токенов ушло на сессию, но не показывает, сколько это стоило.
Провайдер (Polza.AI и подобные) отдаёт стоимость каждого ответа в метаданных, но
DSH её не сохраняет: адаптер приводит ответ к `TokenUsage` — только токены.
Плагин закрывает этот пробел: берёт проекцию сессии `tokenUsage` (четыре
счётчика — некэшированный вход, чтение кэша, запись кэша, выход), умножает на
тариф маршрута `provider/model` и показывает рубли в двух видах:

| Ячейка | Что показывает |
|---|---|
| **сессия** (`data-composer-stat="cost"`) | расход всего лога текущей сессии по тарифу её текущей модели; в ярлыке — модель, по наведению — разбивка по четырём счётчикам |
| **итог** (`data-composer-stat="cost-total"`) | расход **за сегодня** по всем сессиям, которые открывались в этом окне; по наведению — день и неделя с разбивкой по моделям |

## 2. Требования

- **DeepSeek Harness 2.x**, десктопная сборка (Electron). Плагин клиентский, ему
  нужны слот `conversation.composer.dock` и проекции сессии.
- Для установки из репозитория: **Node.js 20+**, **pnpm 9+**, PowerShell 5.1+.
- Собственных зависимостей у плагина нет — только `react`/`react-dom` хоста.
- Тарифы не приходят из сети: они записаны в `client.js` и обновляются вручную
  (см. §5). Без тарифа для маршрута рубли не считаются.

## 3. Установка из репозитория `dsh-bond-plugins`

```powershell
git clone https://github.com/<ваш-логин>/dsh-bond-plugins.git
cd dsh-bond-plugins
powershell -NoProfile -ExecutionPolicy Bypass -File install.ps1
```

Только этот плагин:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File install.ps1 -Only "@local/composer-cost"
```

Посмотреть план, ничего не меняя: `install.ps1 -WhatIf`. Профиль в нестандартном
месте: `-ProfileDir "<путь-к-профилю>"`.

Скрипт делает ровно четыре шага: снимает резервную копию `package.json` и
`cordis.patch.yml` профиля в `<профиль>\backups\<ДД.ММ.ГГГГ>-<ЧЧММСС>`, добавляет
пакет в `dependencies` как `link:` на каталог репозитория, добавляет его в
`dsh.profile.bundles` и запускает `pnpm install` (создаёт junction в
`node_modules` профиля).

После установки — **полный перезапуск DSH**. Клиентская половина подхватывается
только при старте процесса: бандлы кэшируются на время жизни процесса, а кнопка
«перезагрузить плагины» для изменённого `client.js` не годится (пересборка по
ревизиям файлов может уронить web-boot). Если после перезапуска ячеек не видно,
проверьте правила скрытия ниже (нет данных или нет тарифа).

## 4. Как пользоваться

Ячейки стоят в полосе статистики композера, рядом со счётчиками токенов (в доке
они зарегистрированы с порядком 2 и 3).

1. **Ячейка сессии**: `₽ ≈ 12,34 ₽ · deepseek-v4.1-flash-1017`. SVG-знак рубля
   (не эмодзи), сумма в русском формате: пробел-разделитель тысяч (узкий
   неразрывный), запятая перед копейками, суммы меньше копейки — `<0,01`.
2. **Наведение на ячейку сессии** открывает панель: заголовок «Расход сессии
   (оценка)» и строка «≈ N ₽», затем таблица «Вход без кэша / Чтение из кэша /
   Запись в кэш / Выход» — токены, ставка и рубли по каждому счётчику, затем
   «Маршрут» (`provider/model`) и сноска «весь лог сессии по тарифу текущей
   модели». Все четыре строки показываются всегда, даже нулевые: ноль — это
   информация (например, провайдер не сообщает запись в кэш), а не пустота.
3. **Ячейка итога**: `Итого: ≈ 45,67 ₽`. Сумма здесь — **за сегодня**; слово
   «Итого» в ярлыке относится к строке статистики, а не к неделе. По наведению
   открывается панель с двумя разделами: «За день» (дата `ДД.ММ.ГГГГ`) и
   «За неделю» (диапазон `ДД.ММ.ГГГГ — ДД.ММ.ГГГГ`), в каждом — сумма и строки по
   маршрутам моделей; внизу — «данные с ДД.ММ.ГГГГ». Если за неделю ничего нет,
   раздел пишет «Пока не тратилось».
4. **Маршрут без тарифа**: ячейка сессии показывает `— ₽ · <модель>` (без суммы и
   без панели) — это подсказка, какой ключ добавить в таблицу тарифов. В панели
   итога такой маршрут занимает строку со значением «нет тарифа» и в сумму не
   входит.
5. **Нулевой расход**: если сессия ещё не потратила ни одного токена, ячейка
   сессии не рисуется вообще; ячейка итога не рисуется, пока день и неделя оба
   нулевые.

## 5. Настройка

Все параметры — константы в `client.js`; переменных окружения и файлов
конфигурации у плагина нет.

### Тарифы (`TARIFFS`)

Ключ — строго `provider/model`, значение — рубли за 1 млн токенов:

```js
const TARIFFS = {
  "polza/deepseek/deepseek-v4.1-flash-1017": {
    input: 11.530968,      // вход без кэша
    output: 17.1252,       // выход
    cacheRead: 0.76892148, // чтение из кэша
  },
  "polza/minimax/minimax-m3.1-flash": { input: 16.26894, output: 65.07576, cacheRead: 1.626894 },
};
```

Откуда числа: `GET https://polza.ai/api/v1/models/{model}` → `top_provider.pricing`
(₽ за 1M токенов), снято **28.10.2026**. Отдельной ставки за запись в кэш
провайдер не публикует, поэтому `cacheWrite` считается по `input` — это записано
и в коде, и в подписи панели.

Порядок обновления: узнать новый маршрут в ответе ячейки (`— ₽ · <модель>` — это
и есть ключ), поправить `TARIFFS` и перезапустить DSH. Если маршрут вообще
отсутствует в таблице, ячейка останется в виде `— ₽`, а не исчезнет.

### Маршрут по умолчанию (`DEFAULT_ROUTE`)

`polza/deepseek/deepseek-v4.1-flash-1017`. Применяется, только когда сессия не
назвала ни одного маршрута (например, окно шагов уже выгружено из памяти).

### Срок хранения реестра (`LEDGER_KEEP_DAYS`)

`30` дней. Всё, что старше, вычищается при следующей записи в реестр страницы.

### Язык (`DICTIONARIES`)

В этой сборке DSH нет языкового пакета `ru`, интерфейс отвечает как `en`, поэтому
русские подписи лежат в `DICTIONARIES.en`. Английские подписи сохранены
(`ENGLISH`) и включаются заменой `en: RUSSIAN` на `en: ENGLISH`; место `zh`
намеренно занято английским.

## 6. Архитектура кратко

| Половина | Файл | Роль |
|---|---|---|
| Host | `index.js` | пустой `apply()`. Пакет существует как строка Loader; вся работа в браузере |
| Client | `client.js` | два слота `conversation.composer.dock` (id `cost`, order 2 и `cost-total`, order 3), стили, словари |

Что использует клиент:

- **проекция сессии** `tokenUsage` — четыре счётчика всего лога; `modelSelection`
  — `lastUsed`/`next` для маршрута;
- **Chat-селектор** (`useChat`) — последний шаг с `usage.routes[0]`, если проекции
  маршрута не дали;
- **слоты** `ctx.slots.inject/register` и **локаль** `ctx.locale.register`;
- `react-dom.createPortal` (если модуль доступен) — панель рисуется в `document.body`,
  чтобы не обрезалась контейнером статистики; без `react-dom` панель рисуется
  inline над ячейкой.

Состояние:

- расход сессии нигде не хранится — он каждый раз считается из проекции;
- итог за день/неделю живёт в `localStorage` страницы под ключом
  **`dshCost.ledger.v1`** — `{ "ГГГГ-ММ-ДД": { <sessionId>: { route, buckets } } }`.
  Запись делает сама ячейка итога: как только она видит сессию с ненулевыми
  токенами, она кладёт туда её полные суммы (whole-log) по маршруту. Хранится
  30 дней.

Почему `localStorage`, а не HTTP: десктопное окно отдаётся схемой `dsh-app://app`,
откуда ни loopback-маршрут Host, ни его index недоступны, а порт Web GUI от
запуска к запуску меняется. Origin `dsh-app://app` стабилен, поэтому страница —
единственный надёжный контейнер. Параллельный Host-реестр ведёт пакет
`@local/composer-cost-day` (см. его README); текущая ячейка итога его не читает.

## 7. Ограничения и типичные ошибки

- **Всё считается по тарифу одной модели.** `tokenUsage` — строгий объект из
  четырёх счётчиков, провенанса «этот токен ушёл в другую модель» в нём нет.
  Если сессия ходила в две модели, весь её лог оценивается по текущей — отсюда
  сноска в панели.
- **`null`/пусто вместо цифр.** Если тариф маршрута неизвестен, суммы нет: ячейка
  сессии показывает `— ₽ · <модель>`, а в панели итога строка получает «нет
  тарифа» и не входит в сумму. Это не ошибка плагина, а отсутствующий ключ в
  `TARIFFS`.
- **Запись в кэш** у Polza всегда 0: кэш неявный, запись не тарифицируется и не
  сообщается. Строка оставлена намеренно — у провайдера с явной записью она
  заработает.
- **Итог за день не видит фоновые сессии.** В реестр попадает только то, что
  открывалось в этом окне; сессия, работавшая в фоне или в другом окне, войдёт в
  итог, когда её откроют. Точный учёт всех вызовов копится в Host-реестре
  `@local/composer-cost-day`, но ячейка его пока не использует.
- **Очистка данных браузера/`localStorage`** обнуляет день и неделю: реестр
  страницы — единственное хранилище этих сумм. Расход самой сессии при этом
  остаётся корректным — он считается из проекции.
- **Другой компьютер/профиль** — свой реестр; суммы не синхронизируются.
- **Смена тарифов** задним числом пересчитывает и прошлые дни: реестр хранит
  токены, а не рубли — кроме сида (см. ниже).
- **Дневная сумма — прирост, а не весь лог.** `tokenUsage` — тотал всей сессии,
  разделить его по дням нельзя. В день попадает только разница с предыдущим
  чтением этой сессии, поэтому долгоживущая сессия не сбрасывает всю историю в
  «сегодня». Первое чтение сессии и смена модели только задают новую базовую
  линию: прошлое не атрибутируется (именно из-за этого раньше «за день» выходило
  больше реального — весь лог сессий складывался в один день).
- **Данных нет — ячейка честно молчит.** Свежий реестр (или ни одна сессия ещё
  не наблюдалась) показывает `Итого: —`, а не чужую или выдуманную сумму.
  Плагин не содержит вшитых цифр: всё, что он знает, он наблюдает сам.
- **Переключение модели посреди сессии** меняет тариф всей сессии (см. первый
  пункт) — но не «с этого момента».
- Если ячеек нет вовсе: проверьте, что сессия потратила токены и что для её
  маршрута есть тариф, и перезапустите DSH (не ⟳ — см. §3).

## 8. Тесты

Собственного набора тестов у плагина **нет** (`test/` отсутствует): логика —
чистые функции форматирования и React-компоненты, зависящие от проекций хоста.
Проверка ручная:

```powershell
# 1. ячейки видны в композере после перезапуска DSH
# 2. наведение на каждую ячейку открывает панель
# 3. в DevTools: localStorage["dshCost.ledger.v2"] — поля days / seen, сегодняшняя дата и id сессий
# 4. подмена ключа в TARIFFS на несуществующий даёт «— ₽ · <модель>»
```


## Источник цифр «за день» и «за неделю»

Приоритет — **реестр Harness** (`@local/composer-cost-day`): он слушает `llm/stream`
и складывает токены каждого вызова один раз, поэтому видит и сессии, которые в
этом окне не открывались. Клиент читает его по loopback-маршруту
`GET /composer-cost/today`, обновляет раз в 15 с и пишет в сноске панели
«источник: реестр Harness».

Если маршрут недоступен (десктопное окно отдаётся схемой `dsh-app://app`), берётся
запасной путь — собственный реестр страницы в `localStorage`
(`dshCost.ledger.v2`); сноска тогда говорит «источник: страница». Он видит только
сессии, открывавшиеся в окне, и копит прирост с момента первого наблюдения.

Тарифы в `TARIFFS` откалиброваны по дашборду провайдера (03.11.2026: 432,91 ₽ за
день против 101,44 ₽ по каталожной ставке ⇒ ×4,27 для DeepSeek). Если сумма
«за день» начнёт расходиться с `polza-pulse` — правьте коэффициент, не логику.
