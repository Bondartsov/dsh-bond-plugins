# DESIGN — `@local/composer-cost-day`

Host-половина суточного реестра расхода: маршрут, хранилище, подписка на поток
модели и инварианты. Пользовательское описание — в [README.md](../README.md).
Клиентской половины у пакета нет.

## 1. Форма плагина

```js
export const inject = ["webServer"];
export function apply(ctx) { … }
```

`inject` обязателен: при холодном старте записи Loader загружаются раньше, чем
публикуется `webServer`, и `ctx.get('webServer')` вернул бы `undefined`. Loader
держит плагин до публикации службы — это гарантия, а не пожелание.

`apply` создаёт четыре эффекта (каждый — `ctx.effect`, снимается при выгрузке):

| Эффект | Имя | Что делает |
|---|---|---|
| 1 | `composer-cost-day: usage tap` | подписка на `llm/stream` |
| 2 | `composer-cost-day: today route` | `GET /composer-cost/today` |
| 3 | `composer-cost-day: page token` | `webServer.tapIndex` — вставка токена в HTML |
| 4 | `composer-cost-day: last write` | финальный `flush()` при выгрузке |

## 2. Контракт HTTP

| Метод | Путь | Query | Ответ |
|---|---|---|---|
| `GET` | `/composer-cost/today` | `token` = UUID процесса | `200 {version, date, models}` |
| любой другой | там же | — | `405`, пустое тело |

Правила:

- маршрут регистрируется как `kind: "exact"` — без префиксного совпадения;
- проверка токена идёт **до** ответа: `url.searchParams.get("token") !== token` →
  `403`, пустое тело (не JSON — чтобы не подсказывать формат);
- тело ответа: `content-type: application/json; charset=utf-8`,
  `cache-control: no-store`;
- `models` — **сегодняшняя** запись реестра (`days[localDay()] ?? {}`), не весь файл:
  маршрут отвечает на вопрос «сколько сегодня», а не «покажи историю».

Токен: `crypto.randomUUID()` на процесс, живёт только в памяти и в HTML страницы:

```html
<script>window.__DSH_COST_TOKEN__="<uuid>"</script>
```

вставляется `tapIndex` перед `</head>` (если маркера нет — HTML возвращается как
есть). Смысл: loopback-порт доступен любому локальному процессу, поэтому
«страница, которую отдал этот Host» доказывает право читать реестр. Токен
меняется при каждом перезапуске — старый становится недействительным.

## 3. Структура данных

Файл: `<DSH_HOME>/storages/composer-cost/daily.json`
(`DSH_HOME` → иначе `os.homedir()/.dsh`).

```ts
type File = {
  version: 1;
  days: {
    [day: "YYYY-MM-DD"]: {                       // локальная дата машины
      [route: `${provider}/${model}`]: {
        uncached: number;    // inputTokens: некэшированная часть входа
        cacheRead: number;
        cacheWrite: number;
        output: number;
      };
    };
  };
};
```

Семантика счётчиков повторяет проекцию `tokenUsage`, поэтому клиент может
сравнивать реестр с расходом сессии без пересчёта: `inputTokens` — это **только
некэшированная** часть входа, кэш учитывается отдельно.

Счётчик добавляется только для конечных чисел (`Number.isFinite`), иначе `0`:
провайдер может не прислать поле, и это не должно превращать сумму в `NaN`.

## 4. Поток `llm/stream`

```js
ctx.on("llm/stream", (options, next) => {
  const inner = next();
  return (async function* observed() {
    for await (const chunk of inner) {
      if (chunk?.type === "usage" && chunk.usage !== undefined) record(options?.provider, options?.model, chunk.usage);
      yield chunk;
    }
  })();
});
```

Инварианты обёртки:

1. **Наблюдатель, а не фильтр**: каждый чанк отдаётся дальше без изменений;
   порядок и содержимое потока не меняются.
2. `next()` вызывается ровно один раз и до первого `yield`.
3. Запись происходит на чанке `type: "usage"` — это точка, где провайдер
   сообщил расход; других источников у Host нет.
4. Маршрут берётся из `options.provider`/`options.model` вызова, а не из
   последующего состояния: вызов мог быть направлен в другую модель.
5. Нестроковый `provider`/`model` → запись пропускается (ключ был бы мусорным).

## 5. Запись на диск

- **debounce 1500 мс**: один таймер на всплеск; повторные вызовы не сбрасывают его
  (первый вызов назначает, остальные видят `saveTimer !== null`);
- **атомарность**: `writeFile(daily.json.tmp)` → `rename(tmp, daily.json)`. На
  Windows `rename` поверх существующего файла атомарен в пределах тома;
- **prune** выполняется и при загрузке, и перед записью: `KEEP_DAYS = 60`,
  сравнение дат — лексикографическое по `YYYY-MM-DD`;
- **ошибки не фатальны**: `console.warn("[composer-cost] ledger write failed: …")`,
  реестр остаётся в памяти;
- **финальный flush** при выгрузке плагина: если таймер висел, он очищается и
  запись выполняется сразу (не ждём 1.5 с на выходе).

Чтение терпимо к мусору: отсутствующий/битый JSON, чужой `version` или `days` не
объект → пустой реестр, файл будет заменён следующей записью.

## 6. Почему реестр хранит токены, а не рубли

Три причины:

1. **Тариф — клиентское знание.** Таблица `TARIFFS` живёт в `@local/composer-cost`
   и обновляется вручную; дублировать её в Host значит иметь две правды.
2. **Прошлое нельзя переоценивать молча.** Цены меняются; если хранить рубли,
   смена прайса либо исказит историю, либо потребует миграции. Токены
   инвариантны — пересчитать можно в любой момент.
3. **Неизвестный маршрут — штатное состояние.** Реестр принимает любой
   `provider/model`; «нет тарифа» — решение потребителя (ячейка покажет
   `— ₽`), а не повод не учитывать расход.

Отсюда: `rub`, `cost`, `price` в ответе отсутствуют принципиально.

## 7. Отношение к `@local/composer-cost`

```
Host (этот пакет): llm/stream → daily.json → GET /composer-cost/today?token=…
Client (@local/composer-cost): tokenUsage + TARIFFS → ячейки cost / cost-total
```

Сегодня клиентская `TotalSpend` читает `localStorage` страницы, а не этот
маршрут. Причина техническая: десктопное окно отдаётся `dsh-app://app`, откуда
loopback-маршрут Host недоступен, а origin Web GUI (`http://127.0.0.1:<порт>`)
меняется от запуска к запуску. Разделение пакетов сделано ещё и потому, что
Host-код уже смонтированного плагина не перезагружается ⟳, а новый пакет
подхватывается живым.

Переключение потребителя — одна правка `TotalSpend`: `fetch("/composer-cost/today?token="
+ window.__DSH_COST_TOKEN__)` вместо `readPageLedger()`. Формат `models` уже совпадает
с тем, что ожидает `pricedRoutes` (route → четыре счётчика), поэтому
согласование сводится к переименованию полей (`uncached` ↔ `buckets.uncached`).

## 8. Инварианты

1. **Ноль влияния на вызов модели**: поток не меняется, ошибки записи не
   пробрасываются в агента.
2. **Токен — единственная защита**; он не логируется и не попадает в файл.
3. **`403` не раскрывает причину** (пустое тело).
4. **`date` в ответе — локальная дата**, та же, что ключ в `days`; клиент не
   пересчитывает её сам.
5. **Счётчики аддитивны**: повторный ответ увеличивает, ничего не обнуляет.
6. **Файл всегда валиден после успешной записи**: `.tmp` + `rename`.
7. **Память и файл не расходятся больше чем на 1.5 с** (окно debounce).
