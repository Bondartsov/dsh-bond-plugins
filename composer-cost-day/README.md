# composer-cost-day — суточный реестр расхода

`@local/composer-cost-day` — Host-половина без интерфейса. Она слушает поток
модельных вызовов DSH и копит токены **по дням и маршрутам**, чтобы у счётчиков
стоимости был источник «сколько израсходовано за сегодня» по всей машине, а не
только по открытому окну. Деньги она не считает: тарифы живут в клиентской
таблице `@local/composer-cost`, поэтому тарифная таблица в системе одна.

## 1. Что это и какую задачу решает

Клиентская ячейка `cost-total` пакета `@local/composer-cost` считает итог из
`localStorage` страницы — она видит только те сессии, которые открывались в этом
окне. Этот пакет закрывает дыру на стороне Host:

1. подписывается на waterfall `llm/stream` и складывает провайдерский `usage`
   каждого ответа в реестр «день → `provider/model` → четыре счётчика токенов»;
2. хранит реестр в JSON-файле под домашним каталогом DSH, поэтому перезапуск
   приложения не обнуляет утренний расход;
3. отдаёт реестр по loopback-маршруту, защищённому токеном, который этот же
   процесс вставляет в отдаваемую страницу.

Собственного интерфейса, панели и клиентского бандла у пакета нет — в
`package.json` отсутствует секция `dsh.client`.

## 2. Требования

- **DeepSeek Harness 2.x**, десктопная сборка (Electron).
- Host-сервисы: `webServer` (объявлен в `inject`) — без него маршрут не
  регистрируется и пакет не активируется.
- Событие `llm/stream` в композиции профиля (есть в штатной сборке).
- Node.js 20+ и pnpm 9+ — только для установки из репозитория.
- Запись в `<DSH_HOME>/storages/` (по умолчанию `%USERPROFILE%\.dsh\storages`).

## 3. Установка из репозитория `dsh-bond-plugins`

```powershell
git clone https://github.com/<ваш-логин>/dsh-bond-plugins.git
cd dsh-bond-plugins
powershell -NoProfile -ExecutionPolicy Bypass -File install.ps1
```

Только этот пакет:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File install.ps1 -Only "@local/composer-cost-day"
```

План без изменений: `install.ps1 -WhatIf`. Нестандартный профиль:
`-ProfileDir "<путь-к-профилю>"`.

Скрипт снимает резервную копию `package.json` и `cordis.patch.yml` профиля в
`<профиль>\backups\<ДД.ММ.ГГГГ>-<ЧЧММСС>`, добавляет пакет в `dependencies` как
`link:`, добавляет его в `dsh.profile.bundles` и запускает `pnpm install`.

**Это Host-часть.** Клиентских бандлов у неё нет, поэтому перезагрузки плагинов
⟳ недостаточно: новый Host-код загружается только новым процессом. После
установки — **полный перезапуск DSH**. ⟳ нужен лишь для клиентской половины
`@local/composer-cost`, если она обновлялась вместе с этим пакетом.

## 4. Как пользоваться

Интерфейса нет. Пакет работает в фоне, как только загрузился, и делает три вещи:

- **копит**: каждый ответ модели, пришедший чанком `type: "usage"`, добавляется в
  сегодняшнюю запись по своему маршруту;
- **хранит**: `<DSH_HOME>/storages/composer-cost/daily.json` (по умолчанию
  `%USERPROFILE%\.dsh\storages\composer-cost\daily.json`);
- **отдаёт**: `GET /composer-cost/today?token=<токен процесса>` → JSON вида

```json
{
  "version": 1,
  "date": "<ГГГГ-ММ-ДД>",
  "models": {
    "polza/deepseek/deepseek-v4.1-flash-1017": {
      "uncached": 123456,
      "cacheRead": 789012,
      "cacheWrite": 0,
      "output": 23456
    }
  }
}
```

`date` — локальная календарная дата машины (`ГГГГ-ММ-ДД`, машинный формат
контракта). В интерфейсе её показывают как `ДД.ММ.ГГГГ`; конвертацию делает
потребитель.

Проверить вручную (PowerShell), подставив порт из адреса Web GUI и токен из
`window.__DSH_COST_TOKEN__` страницы:

```powershell
(Invoke-WebRequest "http://127.0.0.1:<порт>/composer-cost/today?token=<токен>" -UseBasicParsing).Content
```

Ответы маршрута:

| Код | Когда |
|---|---|
| `200` | токен верный, метод `GET` — тело с реестром |
| `403` | метод правильный, но токен не совпал (пустой ответ, без тела) |
| `405` | метод не `GET` (пустой ответ) |

## 5. Настройка

Файла конфигурации и переменных окружения нет — только константы в `index.js`.

| Константа | Значение | Смысл |
|---|---|---|
| `STORE_VERSION` | `1` | поколение схемы файла; пишется в `{"version": 1, "days": …}`. Менять при изменении формы |
| `SAVE_DEBOUNCE_MS` | `1500` | всплеск вызовов склеивается в одну запись на диск |
| `KEEP_DAYS` | `60` | сколько дней хранится; более старые ключи вычищаются при загрузке и перед каждой записью |
| `ROUTE_PATH` | `/composer-cost/today` | путь маршрута (`kind: "exact"`) |
| `TOKEN_GLOBAL` | `__DSH_COST_TOKEN__` | имя глобальной переменной страницы с токеном |

Домашний каталог DSH берётся из `DSH_HOME`; если переменная не задана —
`%USERPROFILE%\.dsh` (на других ОС — `~/.dsh`).

**Тарифы здесь не настраиваются намеренно.** Реестр хранит токены, а не рубли:
цены меняются, и пересчитывать прошлые дни при смене прайса нельзя. Поэтому
`rub`/`cost` в ответе нет вообще, а «почему `null`» — это про потребителя: если
маршрута нет в `TARIFFS` клиента, сумма не считается и ячейка показывает
`— ₽ · <модель>`; сам реестр продолжает копиться и никуда не пропадает.

## 6. Архитектура кратко

| Что | Где |
|---|---|
| Host | `index.js` (единственный файл, `export const inject = ["webServer"]`) |
| Client | отсутствует |
| Состояние | память процесса (`days`) + файл `storages/composer-cost/daily.json` |
| Токен доступа | `crypto.randomUUID()` на процесс, в память не пишется |

Поток данных:

```
llm/stream (waterfall) → чанк type=usage → record(provider, model, usage)
        → days[сегодня][`provider/model`] += 4 счётчика → debounce 1.5 с → daily.json
GET /composer-cost/today?token=… → days[сегодня]
```

Используемые сервисы DSH: `ctx.webServer.register` (маршрут),
`ctx.webServer.tapIndex` (вставка токена в `index.html` перед `</head>`),
`ctx.on("llm/stream", (options, next) => …)` — обёртка-наблюдатель, которая
пропускает все чанки без изменений и только читает `usage`.

Запись на диск атомарная: `daily.json.tmp` → `rename`. Ошибка записи не роняет
Host — в консоль уходит `[composer-cost] ledger write failed: …`, а реестр
продолжает жить в памяти до следующей попытки.

## 7. Ограничения и типичные ошибки

- **Счёт идёт с момента запуска этого пакета.** Вызовы, сделанные до установки
  или при выключенном приложении, в реестр не попадут: провенанса токенов по
  маршрутам в логах сессий нет.
- **Повторная попытка (retry) считается каждым своим ответом** — провайдер выставил
  токены, значит расход был.
- **Реестр не чинит тарифы.** Если маршрут неизвестен клиенту, сумма не
  появится: пакет отдаёт только токены.
- **Текущая ячейка `cost-total` его не читает.** Десктопная страница отдаётся
  схемой `dsh-app://app`, откуда loopback-маршрут Host недоступен, а порт Web GUI
  меняется. Реестр копится независимо и готов стать источником, когда страница
  начнёт отдаваться с origin Host.
- **`403` при ручной проверке** — почти всегда забытый `?token=…` или токен от
  другого запуска: он новый у каждого процесса, поэтому после перезапуска
  приложения старый токен недействителен.
- **`404` на маршруте** — пакет не загрузился: проверьте, что он в
  `dsh.profile.bundles`, и перезапустите DSH (⟳ Host-код не перезагружает).
- **Нет файла `daily.json`** — это нормально до первого вызова модели либо если
  писать некуда; смотрите консоль Host на `ledger write failed`.
- **`days` очищается**: после 60 дней данные за старые дни удаляются без
  возможности восстановления.
- **Граница дня — локальная полночь**; переводить часы назад в течение дня не
  рекомендуется: часть токенов может попасть в «будущую» дату.
- **Несколько экземпляров DSH на одном `DSH_HOME`** будут перезаписывать файл
  друг друга (последний победил) — профиль должен быть один.

## 8. Тесты

Собственного набора тестов у пакета **нет** (`test/` отсутствует): вся логика —
это подписка на событие и HTTP-ответ, проверяемые в живом Host. Проверка ручная:

```powershell
# 1. после перезапуска DSH сделать один запрос к модели
# 2. убедиться, что появился файл:
Get-Content "$env:USERPROFILE\.dsh\storages\composer-cost\daily.json"
# 3. структура: {"version":1,"days":{"ГГГГ-ММ-ДД":{"provider/model":{uncached,cacheRead,cacheWrite,output}}}}
# 4. GET /composer-cost/today?token=… отдаёт сегодняшний день; без токена — 403
```
